# Lekcja 3.3 — `for`

## Cel
Po lekcji uczeń:
- Pisze pętlę w trzech formach: z licznikiem, z samym warunkiem, nieskończoną
- Używa `break` i `continue` świadomie
- Zna nową formę `for i := range n` (Go 1.22+) i wie, że stara forma też jest poprawna
- Rozumie, że w Go **nie ma `while`** — bo `for` go zastępuje

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Masz zrobić 20 przysiadów. Jak pilnujesz, żeby zrobić dokładnie 20, a nie 18 albo 25?"

**Co chcesz usłyszeć:** liczę w głowie; zaczynam od zera, po każdym dodaję jeden, przy 20 kończę.

**Drugie pytanie:**
> "A teraz inne zadanie: ćwiczysz, **dopóki nie zmęczysz się**. Co jest tu inne? Ile powtórzeń zrobisz?"

→ nie wiadomo z góry. Warunek jest, ale licznika nie ma.

## Krok 2 — Mostek (10 min)
**Mostek:**
> "Opisałeś dwa rodzaje powtarzania. Wiele języków ma na to dwa osobne słowa. Go ma jedno: `for` — i obsługuje nim oba przypadki."

Uczeń tworzy `kurs/zadania/08-petle/main.go`:

```go
package main

import "fmt"

func main() {
	for i := 0; i < 5; i++ {
		fmt.Println("przysiad numer", i)
	}
}
```

**Pytania — rozbierz nagłówek na trzy części:**
- "`i := 0` — kiedy to się wykonuje?" → raz, na samym początku
- "`i < 5` — kiedy jest sprawdzane?" → przed każdym obiegiem
- "`i++` — kiedy?" → po każdym obiegu
- "Ile razy wypisało? Od jakiej liczby do jakiej?" → 5 razy, od 0 do 4

> "Programiści liczą od zera. To będzie miało sens w module 4, przy kolekcjach. Na razie: przy `i < 5` masz dokładnie 5 obiegów, a to najwygodniejsza własność."

## Krok 3 — Eksperyment (15-20 min)

1. **Zmiana granic** — uczeń zmienia `i < 5` na `i <= 5`. Ile obiegów teraz? Dlaczego 6?
2. **Skok co dwa** — `i += 2` zamiast `i++`. Co się wypisze?
3. **W dół** — `for i := 5; i > 0; i--`. Uczeń pisze odliczanie do startu rakiety.
4. **Forma z samym warunkiem** (odpowiednik `while` z innych języków):
   ```go
   licznik := 0
   for licznik < 3 {
       fmt.Println("obieg", licznik)
       licznik++
   }
   ```
   > "Zniknęły dwie części nagłówka. Co się stanie, jeśli usuniesz `licznik++`?"
   → pętla nieskończona. Niech uczeń **spróbuje** i przerwie ją Ctrl+C. To ważne doświadczenie.
5. **Pętla nieskończona z wyjściem:**
   ```go
   suma := 0
   for {
       suma += 10
       if suma > 50 {
           break
       }
   }
   fmt.Println("suma:", suma)
   ```
   > "`for` bez niczego = w kółko. Co przerywa?" → `break`
6. **`continue`:**
   ```go
   for i := 1; i <= 10; i++ {
       if i%2 != 0 {
           continue
       }
       fmt.Println(i)
   }
   ```
   > "Co się wypisało? Co robi `continue` — kończy pętlę czy jeden obieg?"
   (tu wraca `%` z lekcji 2.2 — parzystość)
7. **Nowa forma (Go 1.22+)** — uczeń pisze:
   ```go
   for i := range 5 {
       fmt.Println(i)
   }
   ```
   > "Ten sam wynik co w pierwszym przykładzie, o połowę mniej pisania. Kiedy ta forma nie wystarczy?"
   → gdy chcesz zacząć od innej liczby, iść w dół albo skakać co dwa.
   > "Jeśli licznik nie jest ci potrzebny, można jeszcze krócej: `for range 5 { ... }`"

## Krok 4 — Pogłębienie (10-15 min)

**Pętla w pętli** — uczeń pisze tabliczkę mnożenia:
```go
for i := 1; i <= 3; i++ {
	for j := 1; j <= 3; j++ {
		fmt.Printf("%d*%d=%d\t", i, j, i*j)
	}
	fmt.Println()
}
```
**Pytania:**
- "Ile razy w sumie wykona się `Printf`?" → 9
- "Co robi samo `fmt.Println()` na końcu?" → przechodzi do nowej linii po każdym wierszu
- "Gdyby zewnętrzna miała 3 obiegi, a wewnętrzna 100 — ile razem?" → 300. Pętle się mnożą, nie dodają. To pierwsza intuicja o kosztach.

**`break` w zagnieżdżeniu** — uczeń sprawdza:
```go
for i := 0; i < 3; i++ {
	for j := 0; j < 3; j++ {
		if j == 1 {
			break
		}
		fmt.Println(i, j)
	}
}
```
> "Którą pętlę przerwał `break` — wewnętrzną czy obie?" → tylko wewnętrzną.
Żeby przerwać obie, potrzeba **etykiety**:
```go
zewnetrzna:
	for i := 0; i < 3; i++ {
		for j := 0; j < 3; j++ {
			if i*j > 2 {
				break zewnetrzna
			}
		}
	}
```
> "To rzadko potrzebne. Pokazuję, żebyś wiedział, że istnieje, gdy zobaczysz w cudzym kodzie."

**Czego w Go nie ma:**
- `while` — jest `for warunek`
- `do { } while` — trzeba `for { ... if !warunek { break } }`
- pętli `foreach` w osobnej postaci — jest `for ... range` (moduł 4)

**Zmienna pętli w Go 1.22+** — ważna zmiana:
```go
for i := range 3 {
	fmt.Println(i)
}
```
> "W każdym obiegu `i` jest **nową zmienną**. Do Go 1.21 była jedna, wspólna dla wszystkich obiegów, co powodowało zaskakujące błędy przy funkcjach i goroutine. Jeśli zobaczysz w tutorialu linię `i := i` na początku pętli — to obejście problemu, którego już nie ma."

To wróci w 5.2 (domknięcia) i 11.1 (goroutine).

## Pułapki
- **Pętla nieskończona przez zapomniany `i++`** — program wisi. Ratunek: Ctrl+C. Warto, żeby uczeń **celowo** to wywołał i przerwał, żeby się nie przestraszył, gdy stanie się przypadkiem.
- **Błąd o jeden** (`i <= n` zamiast `i < n`) — najczęstszy błąd w programowaniu w ogóle. Przy 5 obiegach: `i < 5` daje 0,1,2,3,4; `i <= 5` daje sześć obiegów.
- **Zmiana licznika w środku pętli** — legalne, ale prowadzi do nieczytelnego kodu i przypadkowych nieskończoności.
- **`break` przerywa tylko najbliższą pętlę** — najczęstsze nieporozumienie przy zagnieżdżeniach.
- **`continue` w pętli z warunkiem (bez licznika w nagłówku)** — jeśli zwiększenie licznika jest po `continue`, pętla stanie w miejscu. Klasyczna pułapka:
  ```go
  i := 0
  for i < 10 {
      if i%2 == 0 {
          continue   // ← licznik nigdy nie rośnie, pętla wisi
      }
      i++
  }
  ```
  Warto, żeby uczeń to zobaczył.
- **`for i := range 5` wymaga Go 1.22+** — na starszej wersji błąd składni. Sprawdź `go version`.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **`for i := range n`** (1.22) — ucz **obu** form. Klasyczna `for i := 0; i < n; i++` jest w każdym istniejącym kodzie, nowa jest krótsza w najczęstszym przypadku.
- **Zmienna pętli nowa w każdym obiegu** (1.22) — konsekwencje zobaczysz w 5.2 i 11.1. Tu wystarczy fakt.
- `for x := range funkcja` (iteratory, 1.23) — **poza kursem**. Jeśli uczeń zobaczy `range slices.All(s)`, powiedz: "to nowszy sposób iterowania, dojdziesz do niego później".

## Notatki tutora
- **To najważniejsza lekcja modułu 3.** Nie skracaj. Jeśli brakuje czasu, lepiej podzielić na dwie sesje (formy pętli / zagnieżdżenia i `break`) niż przelecieć.
- **Pozwól uczniowi zrobić pętlę nieskończoną i ją przerwać.** Kontrolowana porażka teraz oszczędza panikę później.
- **Uczeń liczy od zera z trudem.** Wracaj do tego: `i < 5` daje pięć obiegów, `i` idzie 0..4. Zapisz w notatkach, jeśli uczeń się myli — wróci w module 4 przy indeksach.
- Nie wprowadzaj `range` po slice'ach ani mapach — to 4.4. Tutaj `range` tylko po liczbie.
- FizzBuzz jest klasykiem rozmów kwalifikacyjnych. Jeśli uczeń go napisze sam — powiedz mu o tym. Motywuje.
