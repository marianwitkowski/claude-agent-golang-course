# Lekcja 3.2 — `switch`

## Cel
Po lekcji uczeń:
- Zamienia łańcuch `else if` na czytelniejszy `switch`
- Używa `case` z wieloma wartościami i gałęzi `default`
- Zna `switch` bez wyrażenia (zamiennik długiego `else if`)
- Wie, że w Go **nie trzeba pisać `break`** — i dlaczego to duża zmiana wobec innych języków

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Automat z napojami: naciskasz przycisk 1 — kawa, 2 — herbata, 3 — woda. Gdybyś opisywał działanie automatu komuś przez telefon, powiedziałbyś 'jeśli 1 to kawa, a jeśli nie i jest 2 to herbata, a jeśli nie i jest 3 to woda'?"

**Co chcesz usłyszeć:** nie — powiedziałbym po prostu "przycisk 1: kawa, 2: herbata, 3: woda". To lista, nie łańcuch warunków.

## Krok 2 — Mostek (5 min)
**Mostek:**
> "Go ma zapis dokładnie na taką listę. Nazywa się `switch`."

Uczeń pisze w `kurs/zadania/07-switch/main.go`:

```go
package main

import "fmt"

func main() {
	przycisk := 2

	switch przycisk {
	case 1:
		fmt.Println("Kawa")
	case 2:
		fmt.Println("Herbata")
	case 3:
		fmt.Println("Woda")
	default:
		fmt.Println("Nie ma takiego przycisku")
	}
}
```

**Pytania:**
- "Porównaj z `else if` z poprzedniej lekcji. Co zniknęło, co się pojawiło?"
- "Co robi `default`?" → gałąź na wszystko, co nie pasowało; odpowiednik ostatniego `else`
- "Zmień `przycisk` na `9`. Co się wypisze?"

## Krok 3 — Eksperyment (10-15 min)

1. **Brak `break`** — uczeń ustawia `przycisk := 1` i sprawdza, czy wypisze się tylko "Kawa", czy też "Herbata" i "Woda".
   → tylko "Kawa". Go kończy `switch` po wykonaniu pasującej gałęzi.
   > "W wielu językach trzeba na końcu każdej gałęzi napisać `break`, bo inaczej program leci dalej. Zapomniany `break` to klasyczne źródło błędów. Go odwrócił domyślne zachowanie. Zysk?"
2. **`fallthrough`** — uczeń dopisuje w gałęzi `case 1:` na końcu słowo `fallthrough` i uruchamia.
   → wypisze "Kawa" **i** "Herbata".
   > "Da się mieć stare zachowanie, ale trzeba o nie poprosić wprost. Jak myślisz, jak często go zobaczysz w prawdziwym kodzie?" → prawie nigdy.
3. **Wiele wartości w jednym `case`:**
   ```go
   dzien := "sobota"

   switch dzien {
   case "sobota", "niedziela":
       fmt.Println("Weekend")
   case "poniedziałek", "wtorek", "środa", "czwartek", "piątek":
       fmt.Println("Dzień roboczy")
   default:
       fmt.Println("To nie jest dzień tygodnia")
   }
   ```
   > "Napisz to samo przez `else if`. Które jest czytelniejsze?"
4. **`switch` bez wyrażenia** — uczeń przepisuje przykład z kurtką z lekcji 3.1:
   ```go
   temperatura := 10

   switch {
   case temperatura < 0:
       fmt.Println("Kurtka zimowa")
   case temperatura < 15:
       fmt.Println("Kurtka jesienna")
   default:
       fmt.Println("Bez kurtki")
   }
   ```
   > "Zauważ: po `switch` nie ma nic. Co w takim razie sprawdzają gałęzie `case`?"
   → same warunki logiczne. `switch` bez wyrażenia = `switch true`.
   > "Porównaj z wersją `else if` z poprzedniej lekcji. Która się lepiej czyta?"
5. **Instrukcja inicjująca** — działa jak w `if`:
   ```go
   switch reszta := liczba % 3; reszta {
   case 0:
       fmt.Println("podzielna przez 3")
   default:
       fmt.Println("reszta:", reszta)
   }
   ```

## Krok 4 — Pogłębienie (10 min)

**Kiedy `switch`, a kiedy `if`?**
| Sytuacja | Wybierz |
| --- | --- |
| Jedna decyzja tak/nie | `if` |
| Dwie gałęzie | `if` / `else` |
| Trzy i więcej wartości tej samej zmiennej | `switch` z wyrażeniem |
| Trzy i więcej **różnych** warunków | `switch` bez wyrażenia |

**Gałąź pusta jest legalna:**
```go
switch znak {
case ' ', '\t':
	// celowo nic nie robimy
default:
	fmt.Println("znak:", znak)
}
```
> "Kiedy 'nic nie rób' jest sensowną decyzją?" → gdy chcesz jawnie powiedzieć: ten przypadek znam i świadomie pomijam.

**`switch` na typach** — istnieje i jest bardzo ważny, ale wymaga interfejsów:
```go
switch v := cos.(type) {
case int:
	...
}
```
> "Zapamiętaj, że coś takiego istnieje. Wrócimy do tego w module 8, gdy będziesz miał do tego potrzebę."

**Uwaga o kolejności:** w `switch` bez wyrażenia gałęzie sprawdzane są **od góry**, dokładnie jak `else if`. Pułapka z kolejnością warunków z lekcji 3.1 obowiązuje tak samo.

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "switch". Sugerowane:
- 🔥 Numer miesiąca (1-12) → nazwa miesiąca, `default` na nieprawidłowy numer
- ⭐ Kalkulator: dwie liczby i znak działania (`+`, `-`, `*`, `/`) wczytane od użytkownika, `switch` po znaku, dzielenie przez zero obsłużone
- ⚡ Numer miesiąca → pora roku, przy użyciu `case` z wieloma wartościami; potem przepisz to na `switch` bez wyrażenia i porównaj, która wersja jest krótsza

Kod ucznia: `kurs/zadania/07-switch/`.

## Pułapki
- **Odruch pisania `break`** — jeśli uczeń zna inny język, będzie je dopisywał. `break` w `switch` w Go jest legalny, ale zbędny (i `gofmt` go nie usunie). Nazwij to wprost.
- **`fallthrough` musi być ostatnią instrukcją w gałęzi** — inaczej błąd kompilacji.
- **`fallthrough` przechodzi do następnej gałęzi bez sprawdzania jej warunku.** To zaskakuje. Dlatego prawie się go nie używa.
- **Typy w `case` muszą pasować do wyrażenia** — `switch liczba { case "tekst": }` → `cannot convert "tekst" to type int`.
- **`default` nie musi być na końcu** (może być gdziekolwiek), ale zawsze pisz go na końcu — inaczej mylisz czytelnika.
- **Duplikat w `case`** — `case 1: ... case 1:` → `duplicate case 1 in switch`. Kompilator to łapie, tylko dla wartości stałych.

## Notatki tutora
- **Najmocniejszy moment tej lekcji to brak `break`.** Jeśli uczeń kiedyś zetknie się z C, Javą czy JavaScriptem, doceni tę decyzję. Nawet jeśli nie — pokazuje sposób myślenia autorów Go: domyślne zachowanie ma być tym bezpieczniejszym.
- **Nie wchodź w `switch` po typach.** Uczeń nie ma jeszcze interfejsów. Jedno zdanie zapowiedzi wystarczy.
- Jeśli uczeń pyta "to kiedy w ogóle używać `if`" — odpowiedz: "gdy masz jedną decyzję. `switch` przy jednej decyzji to armata na muchę".
