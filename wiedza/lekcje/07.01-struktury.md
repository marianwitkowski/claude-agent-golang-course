# Lekcja 7.1 — Struktury

## Cel
Po lekcji uczeń:
- Definiuje własny typ przez `struct` i tworzy jego wartości
- Sięga po pola przez kropkę i je zmienia
- Buduje slice struktur — najczęstszą strukturę danych w prawdziwych programach
- Wie, że struktura jest kopiowana przy przypisaniu i przekazywaniu

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Chcesz zapisać dane trzech osób: imię, wiek, miasto. Masz slice'y z modułu 4 — jak to zrobisz?"

**Co chcesz usłyszeć:** trzy slice'y — `imiona`, `wieki`, `miasta` — i pilnowanie, że indeks 0 w każdym to ta sama osoba.

**Drugie pytanie — tu ma zaboleć:**
> "Teraz usuń drugą osobę. Ile slice'ów musisz poprawić? A co, jeśli pomylisz się w jednym?"

→ dane się rozjeżdżają i nikt tego nie zauważy.

## Krok 2 — Mostek (10 min)
**Mostek:**
> "Potrzebujesz **jednego pudełka na całą osobę**, nie trzech osobnych szuflad. W Go nazywa się to `struct` — struktura."

Uczeń tworzy `kurs/zadania/19-struktury/main.go`:

```go
package main

import "fmt"

type Osoba struct {
	Imie   string
	Wiek   int
	Miasto string
}

func main() {
	a := Osoba{Imie: "Anna", Wiek: 30, Miasto: "Kraków"}

	fmt.Println(a)
	fmt.Println(a.Imie)
	fmt.Printf("%+v\n", a)
}
```

**Pytania:**
- "`type Osoba struct` — co robi ta linia?" → tworzy **nowy typ**, obok `int`, `string` i reszty
- "Czym różni się wynik `Println(a)` od `Printf(\"%+v\")`?" → `%+v` pokazuje nazwy pól. Bardzo przydatne przy diagnostyce.
- "Czemu pola pisane wielką literą?" → z 5.3: wielka litera = widoczne poza pakietem. W jednym pliku małe też działają.
- "`a.Imie` — gdzie już widziałeś kropkę?" → `fmt.Println` — pakiet.funkcja. Tu: zmienna.pole.

## Krok 3 — Eksperyment (15-20 min)

1. **Zmiana pola:**
   ```go
   a.Wiek = 31
   a.Miasto = "Gdańsk"
   fmt.Printf("%+v\n", a)
   ```
2. **Wartość zerowa struktury:**
   ```go
   var pusta Osoba
   fmt.Printf("%+v\n", pusta)   // {Imie: Wiek:0 Miasto:}
   ```
   > "Co jest w polach? Pamiętasz wartości zerowe z 2.1?" → każde pole dostaje wartość zerową swojego typu. **Nie ma niezainicjowanej struktury.**
3. **Trzy sposoby tworzenia:**
   ```go
   a := Osoba{Imie: "Anna", Wiek: 30, Miasto: "Kraków"}   // z nazwami — TAK
   b := Osoba{"Piotr", 25, "Łódź"}                         // po kolei — kruche
   var c Osoba                                             // same zera
   c.Imie = "Ewa"
   ```
   > "Co się stanie z wariantem `b`, gdy dopiszesz do struktury czwarte pole?" → przestanie się kompilować. A gdy zamienisz kolejność pól? → skompiluje się i **po cichu** przypisze złe wartości.
   **Zasada kursu: zawsze z nazwami pól.**
4. **Slice struktur** — najważniejszy wzorzec:
   ```go
   ludzie := []Osoba{
       {Imie: "Anna", Wiek: 30, Miasto: "Kraków"},
       {Imie: "Piotr", Wiek: 25, Miasto: "Łódź"},
   }

   for _, o := range ludzie {
       fmt.Printf("%s (%d) z %s\n", o.Imie, o.Wiek, o.Miasto)
   }
   ```
   > "Porównaj z trzema slice'ami z kroku 1. Co się poprawiło?"
   > "Zwróć uwagę, że wewnątrz `[]Osoba{...}` nie trzeba powtarzać słowa `Osoba` — Go wie."
5. **Struktura jest kopiowana** — kluczowy eksperyment:
   ```go
   oryginal := Osoba{Imie: "Anna", Wiek: 30}
   kopia := oryginal
   kopia.Wiek = 99

   fmt.Println(oryginal.Wiek, kopia.Wiek)   // 30 99
   ```
   > "Oryginał nietknięty. Czym to się różni od slice'a z lekcji 4.2?"
   → slice dzielił magazyn, struktura jest kopiowana w całości. **Struktury zachowują się jak `int`, nie jak slice.**
6. **Konsekwencja w funkcji i w `range`:**
   ```go
   func postarz(o Osoba) {
       o.Wiek++            // zmienia kopię
   }

   func main() {
       a := Osoba{Imie: "Anna", Wiek: 30}
       postarz(a)
       fmt.Println(a.Wiek)   // 30 — bez zmian

       for _, o := range ludzie {
           o.Wiek++          // też kopia — bez efektu
       }
       fmt.Printf("%+v\n", ludzie)

       for i := range ludzie {
           ludzie[i].Wiek++  // przez indeks — działa
       }
       fmt.Printf("%+v\n", ludzie)
   }
   ```
   > "Znasz to z 4.4 i 5.1. Jak zmienić strukturę wewnątrz funkcji?" → wskaźniki, następna lekcja

## Krok 4 — Pogłębienie (10 min)

**Struktura w strukturze:**
```go
type Adres struct {
	Ulica string
	Miasto string
}

type Klient struct {
	Imie  string
	Adres Adres
}

k := Klient{Imie: "Anna", Adres: Adres{Ulica: "Długa 5", Miasto: "Kraków"}}
fmt.Println(k.Adres.Miasto)
```
> "Kropki się łączą. Ile poziomów zagnieżdżenia to za dużo?" (odpowiedź praktyczna: trzy to już sygnał ostrzegawczy)

**Porównywanie struktur** — działa, inaczej niż slice'y:
```go
a := Osoba{Imie: "Anna", Wiek: 30}
b := Osoba{Imie: "Anna", Wiek: 30}
fmt.Println(a == b)   // true
```
> "Kiedy to nie zadziała?" → gdy struktura ma pole typu slice lub mapa. Wtedy `==` nie kompiluje się w ogóle. Do porównania jest wtedy `reflect.DeepEqual` (albo porównanie pole po polu).

**Struktura jako klucz mapy** — działa, jeśli wszystkie pola są porównywalne:
```go
liczniki := map[Osoba]int{}
liczniki[a]++
```

**Funkcja tworząca (konstruktor)** — konwencja Go:
```go
func NowaOsoba(imie string, wiek int) (Osoba, error) {
	if imie == "" {
		return Osoba{}, errors.New("imię nie może być puste")
	}
	return Osoba{Imie: imie, Wiek: wiek}, nil
}
```
> "Go nie ma konstruktorów jako osobnej konstrukcji języka. To zwykła funkcja z nazwą zaczynającą się od `Nowy`/`New`. Kiedy jej potrzebujesz?" → gdy tworzenie wymaga sprawdzenia poprawności albo ustawienia pól nieoczywistych

**Struktury a JSON** — zapowiedź 9.2:
```go
type Produkt struct {
	Nazwa string `json:"nazwa"`
	Cena  float64 `json:"cena"`
}
```
> "Te dopiski w grawisach to znaczniki (tagi) — instrukcja dla biblioteki, jak zapisać strukturę do pliku. Wrócimy w module 9."

## Pułapki
- **Tworzenie bez nazw pól** — przy zmianie kolejności pól kompiluje się i przypisuje złe wartości. Zawsze z nazwami.
- **Struktura jest kopiowana** — zmiana wewnątrz funkcji albo w `range` nie działa. Najczęstsze zaskoczenie tej lekcji.
- **Duża struktura kopiowana w pętli** — kosztowne. Przy dużych danych używa się wskaźników (7.2).
- **`==` nie działa na strukturze z polem slice/mapa** — błąd kompilacji, nie cichy problem. To akurat dobra wiadomość.
- **Pola z małej litery są niewidoczne poza pakietem** — i, co ważniejsze, **niewidoczne dla `encoding/json`** (moduł 9). Klasyczny problem: "czemu mój JSON jest pusty".
- **Wskaźnik `nil` do struktury** — `var p *Osoba; p.Imie` → panika. Wskaźniki w 7.2.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- `new(wyrażenie)` (1.26) — `new` przyjmuje teraz wartość początkową, co upraszcza pola opcjonalne: `Wiek: new(30)`. Ciekawostka; uczeń pozna `new` dopiero przy wskaźnikach.
- Struktury o znanym rozmiarze bywają od 1.26 alokowane na stosie — szybciej, bez zmian w kodzie.

## Notatki tutora
- **Motywacja z kroku 1 (trzy równoległe slice'y) jest ważna.** Struktura bez tego bólu wygląda jak zbędna ceremonia.
- **Eksperyment 5 i 6 razem** — struktura kopiowana kontra slice współdzielony. To trzecie spotkanie ucznia z tym rozróżnieniem (4.2, 5.1, 7.1). Za każdym razem warto je nazwać, bo dopiero powtórzenie utrwala.
- **Nie wprowadzaj metod** — to 7.2. Jeśli uczeń pyta "a czy struktura może coś robić?" → "brawo, dokładnie o tym jest następna lekcja".
- Nie tłumacz układu struktury w pamięci ani wyrównania pól. Poza kursem.
- Jeśli uczeń zna klasy z innego języka i pyta "czy to jest klasa" — powiedz: "struktura to same dane; zachowanie dokłada się osobno, w 7.2. Go rozdziela te dwie rzeczy celowo."
