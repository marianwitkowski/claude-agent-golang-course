# Lekcja 4.3 — Mapy

## Cel
Po lekcji uczeń:
- Tworzy mapę i sięga po wartość przez klucz
- Używa idiomu `wartosc, ok := mapa[klucz]` i wie, po co jest `ok`
- Dodaje, zmienia i usuwa wpisy
- Rozumie, kiedy wybrać mapę, a kiedy slice

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Szukasz numeru telefonu do Anny. Masz dwie możliwości: kartka z 200 numerami w kolejności wpisywania, albo książka telefoniczna. Ile miejsc sprawdzisz w każdym przypadku?"

**Co chcesz usłyszeć:** na kartce trzeba przejrzeć wszystko po kolei; w książce idziesz prosto do "A".

**Drugie pytanie:**
> "W książce szukasz po nazwisku, nie po numerze porządkowym. Czym się różni 'nazwisko' od 'pozycja 47'?"

→ nazwisko coś znaczy, numer pozycji jest przypadkowy.

## Krok 2 — Mostek (10 min)
**Mostek:**
> "Slice z poprzednich lekcji to ta kartka — dostajesz się przez numer pozycji. **Mapa** to książka telefoniczna: dostajesz się przez klucz, który sam wybierasz."

Uczeń tworzy `kurs/zadania/11-mapy/main.go`:

```go
package main

import "fmt"

func main() {
	telefony := map[string]string{
		"Anna":  "601-234-567",
		"Piotr": "602-345-678",
	}

	fmt.Println(telefony["Anna"])
	fmt.Println(len(telefony))
}
```

**Pytania:**
- "`map[string]string` — co znaczy pierwszy `string`, a co drugi?" → typ klucza, typ wartości
- "Porównaj `telefony[\"Anna\"]` z `oceny[0]` z lekcji 4.1. Co jest w nawiasach kwadratowych?"
- "Zwróć uwagę na przecinek po ostatnim wpisie. Usuń go i zobacz." → `syntax error`. Go **wymaga** przecinka po ostatnim elemencie w zapisie wieloliniowym. To dziwne, ale ułatwia dopisywanie linii.

Nazwij: **mapa**, **klucz**, **wartość**.

## Krok 3 — Eksperyment (15 min)

1. **Klucz, którego nie ma:**
   ```go
   fmt.Println(telefony["Kowalski"])
   ```
   > "Co się wypisało? Program padł?"
   → pusta linia. Mapa zwraca **wartość zerową** typu wartości (tu: pusty tekst). Żadnego błędu.
   > "Czym to się różni od `oceny[99]` w slice?" → tam był `panic`, tu cisza. To ma konsekwencje.
2. **Mapa liczb** — uczeń pisze:
   ```go
   punkty := map[string]int{"Anna": 10}
   fmt.Println(punkty["Anna"], punkty["Nikt"])
   ```
   → `10 0`
   > "Anna ma 10 punktów, a Nikt ma 0. Ale czy Nikt naprawdę **ma zero punktów**, czy go po prostu **nie ma w mapie**? Jak je odróżnisz?"
   → tu ma zaboleć. To motywuje kolejny krok.
3. **Idiom `, ok`** — odpowiedź na to pytanie:
   ```go
   wartosc, ok := punkty["Nikt"]
   fmt.Println(wartosc, ok)     // 0 false

   if p, ok := punkty["Anna"]; ok {
       fmt.Println("Anna ma", p, "punktów")
   } else {
       fmt.Println("Anny nie ma w rankingu")
   }
   ```
   > "Ten zapis `if x, ok := ...; ok` — pamiętasz instrukcję inicjującą z lekcji 3.1?"
   > "`ok` to `bool`. Co znaczy `true`?" → klucz istnieje w mapie
4. **Dodawanie, zmiana, usuwanie:**
   ```go
   punkty["Piotr"] = 7        // dodanie
   punkty["Anna"] = 12        // zmiana — ten sam zapis!
   delete(punkty, "Piotr")    // usunięcie
   fmt.Println(punkty, len(punkty))
   ```
   > "Dodanie i zmiana wyglądają identycznie. Skąd Go wie, o co ci chodzi?" → nie musi wiedzieć: klucz albo jest, albo go nie ma
   > "Co zrobi `delete` na kluczu, którego nie ma?" → nic, bez błędu
5. **Mapa pusta i mapa `nil`** — bardzo ważna różnica:
   ```go
   var zepsuta map[string]int      // nil
   dobra := map[string]int{}       // pusta, ale gotowa
   // albo: dobra := make(map[string]int)

   fmt.Println(zepsuta["x"])       // 0 — czytanie DZIAŁA
   dobra["x"] = 1                  // OK
   // zepsuta["x"] = 1             // panic: assignment to entry in nil map
   ```
   > "Z mapy `nil` można czytać, ale nie można do niej pisać. Wypróbuj i zobacz komunikat."
   **Zasada:** mapę zawsze twórz przez `map[K]V{}` albo `make`.
6. **Zliczanie — najczęstsze zastosowanie mapy:**
   ```go
   slowa := []string{"kot", "pies", "kot", "kot", "pies"}
   licznik := map[string]int{}

   for i := 0; i < len(slowa); i++ {
       licznik[slowa[i]]++
   }
   fmt.Println(licznik)   // map[kot:3 pies:2]
   ```
   > "Zwróć uwagę: przy pierwszym `kot` w mapie nie ma nic. Czemu `++` zadziałało?"
   → bo brak klucza daje wartość zerową `0`, a `0++` to `1`. To wygodne i bardzo częste.

## Krok 4 — Pogłębienie (10 min)

**Kolejność w mapie jest losowa** — uczeń wypisuje mapę kilka razy pod rząd:
```go
for i := range 3 {
	fmt.Println(i, licznik)
}
```
Potem uruchamia program 3 razy → kolejność może być inna za każdym razem.
> "To **celowe**. Autorzy Go losują kolejność, żeby nikt nie pisał kodu zależnego od niej. Co byś zrobił, gdybyś potrzebował wyniku w stałej kolejności?"
→ posortować klucze (wróci w 4.4).

**Mapa vs slice — kiedy co:**
| Potrzebujesz | Wybierz |
| --- | --- |
| Kolejność ma znaczenie | slice |
| Dostęp przez "numer po kolei" | slice |
| Dostęp przez nazwę/identyfikator | mapa |
| Sprawdzanie "czy coś tu jest" | mapa |
| Zliczanie wystąpień | mapa |

**Co może być kluczem:** `string`, liczby, `bool` — wszystko, co da się porównać przez `==`.
Czym **nie może**: slice, mapa (nie da się ich porównać).
```go
// m := map[[]string]int{}   // BŁĄD: invalid map key type []string
```

**Mapa jako zbiór** (Go nie ma osobnego typu zbioru):
```go
odwiedzone := map[string]bool{}
odwiedzone["Kraków"] = true

if odwiedzone["Gdańsk"] {
	fmt.Println("byłem")
} else {
	fmt.Println("nie byłem")   // brak klucza → false
}
```
> "Czemu to działa bez `, ok`?" → bo wartością zerową `bool` jest `false`, czyli dokładnie to, czego chcemy.

**Mapa też jest współdzielona** — jak slice z 4.2:
```go
a := map[string]int{"x": 1}
b := a
b["x"] = 999
fmt.Println(a["x"])   // 999
```
> "Znasz to już. Przypisanie kopiuje adres, nie dane."

## Pułapki
- **Zapis do mapy `nil`** → `panic: assignment to entry in nil map`. Zawsze `make` albo `{}`.
- **Brak klucza daje wartość zerową, nie błąd** — `punkty["nikt"]` to `0`, co może wyglądać jak prawdziwy wynik. Gdy różnica ma znaczenie, używaj `, ok`.
- **Kolejność iteracji jest losowa** — kod, który "działał", zacznie dawać inne wyniki. Nigdy nie polegaj na kolejności.
- **Przecinek po ostatnim wpisie jest obowiązkowy** w zapisie wieloliniowym.
- **Mapy nie da się porównać przez `==`** (poza porównaniem z `nil`) → `maps.Equal(a, b)`.
- **Mapa jest współdzielona przy przypisaniu** — jak slice.
- **`delete` na nieistniejącym kluczu nic nie robi** — to cecha, nie błąd, ale bywa myląca przy debugowaniu.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
Pakiet **`maps`** (od 1.21) — pokaż na końcu:
```go
import ("maps"; "slices")

klucze := slices.Sorted(maps.Keys(licznik))   // klucze w kolejności alfabetycznej
fmt.Println(maps.Equal(a, b))
kopia := maps.Clone(licznik)
```
> "`maps.Keys` daje klucze, `slices.Sorted` je porządkuje. To rozwiązanie problemu losowej kolejności."

## Notatki tutora
- **Eksperyment 2 → 3 to serce lekcji:** najpierw uczeń widzi problem (nie odróżnię "zero punktów" od "nie ma takiego"), potem dostaje narzędzie (`, ok`). Nie odwracaj tej kolejności — podane bez problemu, `, ok` wygląda na zbędny rytuał.
- **Zliczanie (eksperyment 6) to najczęstsze prawdziwe zastosowanie mapy.** Warto je przećwiczyć więcej niż resztę.
- **Nie tłumacz tablic haszujących.** "Mapa znajduje po kluczu od razu, niezależnie ile ma wpisów" — tyle wystarczy.
- Nie wprowadzaj `range` po mapie — to 4.4. Tutaj wystarczy wypisanie całej mapy przez `Println`.
- Jeśli uczeń pyta o mapę wewnątrz mapy (`map[string]map[string]int`) — powiedz, że się da, ale że zwykle lepszy jest `struct` (moduł 7). Nie rozwijaj.
