# Lekcja 5.2 — Wariadyczne, funkcje jako wartości, domknięcia

## Cel
Po lekcji uczeń:
- Pisze funkcję przyjmującą dowolną liczbę argumentów
- Przekazuje funkcję jako argument innej funkcji
- Rozumie, czym jest domknięcie i po co bywa potrzebne
- Wie, że od Go 1.22 pętla nie psuje funkcji tworzonych w środku

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "`fmt.Println("a")` i `fmt.Println("a", "b", "c")` — obie działają. Jak myślisz, ile parametrów ma `Println`?"

**Co chcesz usłyszeć:** nie da się powiedzieć — przyjmuje dowolną liczbę.

**Drugie pytanie:**
> "Kelner zapamiętuje twoje zamówienie i wraca z nim za dziesięć minut. W międzyczasie obsługuje innych. Co takiego kelner **nosi ze sobą**, gdy odchodzi od stolika?"

→ pamięć o twoim stoliku. Do tego wrócimy przy domknięciach.

## Krok 2 — Mostek (5-10 min)
**Mostek:**
> "`Println` jest **wariadyczna** — przyjmuje dowolną liczbę argumentów. Ty też możesz taką napisać."

Uczeń tworzy `kurs/zadania/14-funkcje2/main.go`:

```go
package main

import "fmt"

func suma(liczby ...int) int {
	wynik := 0
	for _, l := range liczby {
		wynik += l
	}
	return wynik
}

func main() {
	fmt.Println(suma(1, 2, 3))
	fmt.Println(suma(10))
	fmt.Println(suma())
}
```

**Pytania:**
- "`...int` — czym się różni od `[]int`?" → w wywołaniu podajesz luźne argumenty, nie listę
- "Wewnątrz funkcji: jakiego typu jest `liczby`?" → **slice**. Niech sprawdzi `%T`.
- "Co zwróciło `suma()` bez argumentów?" → 0, bo pętla po pustym slice nie wykonuje obiegu
- "Masz gotowy slice `liczby := []int{1,2,3}` — jak go przekażesz?" → `suma(liczby...)` (trzy kropki z 4.2)

## Krok 3 — Eksperyment (15 min)

1. **Parametr wariadyczny musi być ostatni:**
   ```go
   func opis(prefiks string, liczby ...int) string { ... }   // OK
   // func zle(liczby ...int, prefiks string)                // BŁĄD
   ```
   > "Czemu tylko ostatni? Spróbuj i przeczytaj komunikat." → `can only use ... with final parameter`
2. **Funkcja jako wartość:**
   ```go
   func podwoj(x int) int { return x * 2 }

   func main() {
       f := podwoj              // bez nawiasów!
       fmt.Println(f(5))        // 10
       fmt.Printf("%T\n", f)    // func(int) int
   }
   ```
   > "Co się stanie, jeśli napiszesz `f := podwoj(5)`?" → wtedy w `f` jest wynik (10), nie funkcja. Nawiasy = wywołanie.
3. **Funkcja jako argument:**
   ```go
   func zastosuj(liczby []int, operacja func(int) int) []int {
       wynik := make([]int, 0, len(liczby))
       for _, l := range liczby {
           wynik = append(wynik, operacja(l))
       }
       return wynik
   }

   func main() {
       liczby := []int{1, 2, 3}
       fmt.Println(zastosuj(liczby, podwoj))
   }
   ```
   > "`operacja func(int) int` — co to za typ parametru?" → funkcja przyjmująca `int` i zwracająca `int`
   > "Co zyskujesz? Napisz drugą funkcję `kwadrat` i przekaż ją do tej samej `zastosuj`."
4. **Funkcja bez nazwy (anonimowa):**
   ```go
   fmt.Println(zastosuj(liczby, func(x int) int { return x * x }))
   ```
   > "Nie musisz nadawać nazwy czemuś, czego użyjesz raz."
5. **Domknięcie** — wracamy do kelnera:
   ```go
   func licznik() func() int {
       n := 0
       return func() int {
           n++
           return n
       }
   }

   func main() {
       nastepny := licznik()
       fmt.Println(nastepny(), nastepny(), nastepny())   // 1 2 3

       inny := licznik()
       fmt.Println(inny())                                // 1 — własny licznik
   }
   ```
   > "`n` powstało w `licznik()`, a `licznik()` już się skończyło. Czemu `n` nadal żyje i pamięta wartość?"
   → zwrócona funkcja **nosi je ze sobą**. To jest domknięcie (`closure`).
   > "Czemu `inny` zaczyna od 1?" → bo drugie wywołanie `licznik()` stworzyło własne `n`
6. **Funkcje w pętli** — historia z gwiazdką:
   ```go
   funkcje := []func(){}
   for i := range 3 {
       funkcje = append(funkcje, func() { fmt.Print(i, " ") })
   }
   for _, f := range funkcje {
       f()
   }
   ```
   → Go 1.22+: `0 1 2`
   > "Do Go 1.21 wypisałoby `2 2 2` — bo `i` było **jedną** zmienną, wspólną dla wszystkich obiegów, a wszystkie funkcje nosiły ze sobą tę samą. Od 1.22 każdy obieg ma własne `i`."
   > "Jeśli zobaczysz w tutorialu linijkę `i := i` na początku pętli — to obejście tego problemu. Dziś zbędne."

## Krok 4 — Pogłębienie (10 min)

**Po co komu funkcja jako argument?** Pokaż praktyczny przykład — sortowanie po własnym kryterium:
```go
import "slices"

imiona := []string{"Ewa", "Krzysztof", "Ala"}

slices.SortFunc(imiona, func(a, b string) int {
	return len(a) - len(b)      // ujemne = a przed b
})
fmt.Println(imiona)             // [Ala Ewa Krzysztof]
```
> "`slices.Sort` sortuje alfabetycznie. A gdy chcesz po długości? Biblioteka nie może przewidzieć twojego kryterium — więc przyjmuje je jako funkcję."

**`defer` z domknięciem** — zapowiedź następnej lekcji:
```go
func praca() {
	start := "początek"
	defer func() { fmt.Println("koniec, było:", start) }()
	fmt.Println(start)
}
```
> "Funkcja zapamiętana na później, nosząca ze sobą `start`. Więcej o `defer` w 5.3."

**Typ funkcyjny z nazwą** — uczeń zobaczy to w cudzym kodzie:
```go
type Operacja func(int) int

func zastosuj(liczby []int, op Operacja) []int { ... }
```
> "To ta sama rzecz, tylko z nazwą dla czytelności. Własne typy — moduł 7."

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "funkcje wariadyczne i anonimowe". Sugerowane:
- 🔥 Funkcja `najwiekszy(liczby ...int) int` — bez `slices.Max`, pętlą
- ⭐ Funkcja `filtruj(liczby []int, warunek func(int) bool) []int`; użyj jej dwa razy: raz do parzystych, raz do większych od 10
- ⚡ Napisz `licznikOd(start int) func() int` — domknięcie zaczynające od podanej liczby; stwórz dwa niezależne liczniki i pokaż, że się nie mieszają

## Pułapki
- **Parametr wariadyczny musi być ostatni** i może być tylko jeden.
- **`suma(slice)` vs `suma(slice...)`** — bez trzech kropek dostaniesz `cannot use slice as int value`.
- **Wariadyczna funkcja dostaje slice — czyli współdzielony magazyn.** Zmiana `liczby[0]` wewnątrz zmieni oryginał wywołującego, jeśli przekazano `slice...`. Rzadkie, ale zaskakujące.
- **`f := podwoj` vs `f := podwoj(5)`** — nawiasy decydują, czy przekazujesz funkcję, czy jej wynik.
- **Domknięcie nosi zmienną, nie jej kopię** — jeśli po utworzeniu funkcji zmienisz zmienną, funkcja zobaczy nową wartość.
- **`i := i` w pętli** — jeśli uczeń kopiuje kod z internetu, zobaczy to. Nie jest błędem, jest zbędne od 1.22.
- **Zbyt sprytne domknięcia szybko stają się nieczytelne.** Zasada: jeśli musisz się zastanowić dwie minuty, co ta funkcja pamięta — napisz to zwykłą funkcją.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **Zmienna pętli nowa w każdym obiegu** (1.22) — najważniejsza zmiana dla tej lekcji. Kod, który przed 1.22 wypisywał `2 2 2`, dziś wypisuje `0 1 2`.
- Wraca w 11.1: `for i := range 3 { go func(){ fmt.Println(i) }() }` — przed 1.22 był to klasyczny błąd początkującego.
- `slices.SortFunc` przyjmuje funkcję zwracającą `int` (ujemne/zero/dodatnie). Starsze `sort.Slice` przyjmowało funkcję zwracającą `bool` — uczeń może trafić na obie formy.

## Notatki tutora
- **Domknięcia są trudne.** Jeśli uczeń nie łapie po eksperymencie 5 — nie ciągnij. Powiedz: "to zaawansowana rzecz, wystarczy, że wiesz o istnieniu; wrócimy przy `defer`". Nie każdy potrzebuje tego w pierwszym miesiącu.
- **Funkcja jako argument jest ważniejsza niż domknięcia** — uczeń spotka to natychmiast w `slices.SortFunc`, w `http.HandleFunc`, w testach. Poświęć na to więcej czasu.
- Analogia z kelnerem działa na domknięcia, ale nie ciągnij jej dalej niż do "nosi ze sobą pamięć o kontekście".
- Nie wprowadzaj `map`/`filter`/`reduce` jako pojęć z programowania funkcyjnego. Go nie ma tych funkcji w bibliotece standardowej i uczeń nie potrzebuje terminologii.
- Jeśli uczeń jest przytłoczony — eksperymenty 5 i 6 można przenieść na powtórkę po module 6.
