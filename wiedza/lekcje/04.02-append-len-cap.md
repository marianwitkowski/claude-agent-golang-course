# Lekcja 4.2 — `append`, `len`, `cap`

## Cel
Po lekcji uczeń:
- Dodaje elementy do slice'a przez `append` i rozumie, dlaczego trzeba przypisać wynik
- Odróżnia długość (`len`) od pojemności (`cap`)
- Buduje slice w pętli, zaczynając od pustego
- Wie, że kopiowanie slice'a **nie kopiuje danych**, i umie zrobić prawdziwą kopię

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Idziesz do sklepu z torbą na 10 rzeczy. Masz w niej 3 zakupy. Ile rzeczy **masz**, a ile jeszcze **zmieści się**? To dwie różne liczby, prawda?"

**Drugie pytanie:**
> "Torba się zapełniła, a ty chcesz dołożyć jeszcze coś. Co robisz?"

→ biorę większą torbę i **przekładam** do niej wszystko. Stara torba przestaje być używana.

## Krok 2 — Mostek (10 min)
**Mostek:**
> "Slice ma dokładnie te dwie liczby: `len` to ile masz, `cap` to ile się zmieści bez przeprowadzki. A gdy zabraknie miejsca, Go robi dokładnie to, co ty z torbą."

Uczeń tworzy `kurs/zadania/10-append/main.go`:

```go
package main

import "fmt"

func main() {
	zakupy := []string{"chleb", "mleko", "masło"}
	fmt.Println(len(zakupy), cap(zakupy))

	zakupy = append(zakupy, "jajka")
	fmt.Println(zakupy, len(zakupy), cap(zakupy))
}
```

**Pytania:**
- "Co pokazało `cap` na początku, a co po dodaniu?" → zwykle 3, potem 6 — Go podwaja
- "Zauważ zapis: `zakupy = append(zakupy, ...)`. Czemu wynik trzeba **przypisać z powrotem**?"
  → bo `append` może przenieść dane w nowe miejsce i **zwraca nowy slice**. Stary zostaje bez zmian.

**Eksperyment natychmiastowy** — uczeń pisze samo `append(zakupy, "ser")` bez przypisania:
→ `append(...) evaluated but not used`
> "Kompilator cię pilnuje. Ale zaraz zobaczysz przypadek, w którym nie upilnuje."

## Krok 3 — Eksperyment (15 min)

1. **Wzrost pojemności** — uczeń pisze:
   ```go
   var s []int
   for i := range 10 {
       s = append(s, i)
       fmt.Println(len(s), cap(s))
   }
   ```
   > "Prześledź kolumnę `cap`. Jaki ciąg liczb widzisz?" → 1, 2, 4, 4, 8, 8, 8, 8, 16...
   > "Czemu Go podwaja zamiast dokładać po jednym?" → bo przeprowadzka jest kosztowna; podwajanie sprawia, że zdarza się rzadko.
2. **Budowanie od zera** — najczęstszy wzorzec w Go:
   ```go
   var parzyste []int
   for i := range 20 {
       if i%2 == 0 {
           parzyste = append(parzyste, i)
       }
   }
   fmt.Println(parzyste)
   ```
   > "Zaczynasz od `nil`, a `append` działa. Pamiętasz z 4.1, że na `nil` slice `len` daje 0?"
3. **Dodawanie wielu naraz i sklejanie slice'ów:**
   ```go
   a := []int{1, 2}
   b := []int{3, 4}

   a = append(a, 5, 6)      // kilka wartości
   a = append(a, b...)      // cały drugi slice — zwróć uwagę na trzy kropki
   fmt.Println(a)
   ```
   > "Spróbuj bez trzech kropek. Co mówi kompilator?" → `cannot use b (variable of type []int) as int value`
   Trzy kropki znaczą: "rozsyp ten slice na pojedyncze argumenty". Wróci w 5.2.
4. **Pułapka współdzielenia** — najważniejszy eksperyment lekcji:
   ```go
   oryginal := []int{1, 2, 3}
   kopia := oryginal          // wygląda jak kopia

   kopia[0] = 999
   fmt.Println(oryginal)      // [999 2 3]  ← ZMIENIŁ SIĘ ORYGINAŁ
   ```
   > "Co się stało? Czy `kopia` to naprawdę kopia?"
   → **nie**. Slice to jak adres do wspólnego magazynu, a nie sam magazyn. Przypisanie kopiuje adres, nie dane.
5. **Prawdziwa kopia:**
   ```go
   prawdziwa := make([]int, len(oryginal))
   copy(prawdziwa, oryginal)

   prawdziwa[0] = 111
   fmt.Println(oryginal, prawdziwa)   // oryginał nietknięty
   ```
   Krótszy zapis (od Go 1.21): `prawdziwa := slices.Clone(oryginal)`
6. **`make` z rezerwą** — gdy z góry wiesz, ile będzie elementów:
   ```go
   s := make([]int, 0, 100)   // długość 0, pojemność 100
   fmt.Println(len(s), cap(s))
   ```
   > "Po co rezerwować z góry?" → żeby uniknąć wielu przeprowadzek. Optymalizacja, nie obowiązek.
   Uwaga na różnicę: `make([]int, 5)` daje **pięć zer**, nie pusty slice o pojemności 5.

## Krok 4 — Pogłębienie (10 min)

**`append` i wspólny magazyn — pułapka dla zaawansowanych, ale warto zobaczyć:**
```go
baza := []int{1, 2, 3, 4, 5}
pierwsze := baza[:2]              // [1 2], ale cap = 5!

pierwsze = append(pierwsze, 99)
fmt.Println(baza)                 // [1 2 99 4 5]  ← baza się zmieniła
```
> "`append` miał wolne miejsce w istniejącym magazynie, więc go użył — i nadpisał element bazy. Kiedy tego nie będzie?"
→ gdy zabraknie pojemności i nastąpi przeprowadzka. Czyli **zachowanie zależy od `cap`** — i to jest niebezpieczne.
**Zasada praktyczna dla ucznia:** jeśli robisz `append` na wycinku cudzego slice'a, najpierw zrób `slices.Clone`.

**Usuwanie elementu** — Go nie ma na to funkcji wbudowanej:
```go
s := []string{"a", "b", "c", "d"}
i := 1
s = append(s[:i], s[i+1:]...)     // klasyczny idiom
fmt.Println(s)                     // [a c d]
```
Od 1.21 krócej i czytelniej: `s = slices.Delete(s, 1, 2)`.
> "Rozbierz ten klasyczny zapis: co jest przed `i`, co po `i`, i co robią trzy kropki?"

## Pułapki
- **`append` bez przypisania** — najczęstszy błąd. Tu akurat kompilator ratuje (`evaluated but not used`), ale **nie zawsze**: `append(s[:i], ...)` przypisane do innej zmiennej przejdzie po cichu.
- **Przypisanie slice'a nie kopiuje danych** — źródło "magicznych" zmian w cudzych danych. To pułapka nr 1 tej lekcji.
- **`copy` kopiuje tylko tyle, ile zmieści się w celu** — `copy(make([]int, 2), zrodlo5elementowe)` skopiuje 2 elementy i nie powie ani słowa. Zwracana wartość `copy` mówi ile skopiowano.
- **`make([]int, 5)` vs `make([]int, 0, 5)`** — pierwszy ma pięć zer, drugi jest pusty. Pomyłka daje slice zaczynający się od zer.
- **`cap` rzadko jest ci potrzebny** — poza optymalizacją i zrozumieniem pułapki współdzielenia. Nie każ uczniowi go pilnować.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
Pakiet `slices` skraca prawie wszystko z tej lekcji — pokaż **po** tym, jak uczeń zrobił to ręcznie:
| Ręcznie | Z `slices` |
| --- | --- |
| `copy` + `make` | `slices.Clone(s)` |
| `append(s[:i], s[i+1:]...)` | `slices.Delete(s, i, i+1)` |
| `append(a, b...)` | `slices.Concat(a, b)` (1.22) |
| pętla szukająca | `slices.Contains`, `slices.Index` |
| `sort.Ints(s)` | `slices.Sort(s)` |

Od Go 1.26 slice'y o znanym rozmiarze bywają alokowane na stosie — szybciej, bez zmian w kodzie. Ciekawostka, nie materiał.

## Notatki tutora
- **Eksperyment 4 (współdzielenie) jest sercem lekcji.** Jeśli zabraknie czasu, wytnij `cap`, nie wytnij tego. Uczeń, który tego nie zobaczy, będzie miał w przyszłości błąd, którego nie zrozumie.
- Analogia z torbą działa dobrze, ale ma granice — nie ciągnij jej do współdzielenia. Tam lepsza jest analogia z adresem: dwie osoby mają adres tego samego magazynu.
- **Nie tłumacz wewnętrznej budowy slice'a** (wskaźnik + len + cap). Wystarczy "slice wskazuje na magazyn z danymi".
- Jeśli uczeń pyta "to po co w ogóle `cap`, skoro Go sam zarządza" — dobra odpowiedź: "żebyś rozumiał, czemu czasem `append` zmienia cudze dane, a czasem nie".
- Ta lekcja jest gęsta. Jeśli uczeń jest zmęczony po eksperymencie 4 — krok 4 (współdzielenie przy `append` na wycinku) przenieś do 4.4.
