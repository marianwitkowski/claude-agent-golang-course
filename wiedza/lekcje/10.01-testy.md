# Lekcja 10.1 — Testy

## Cel
Po lekcji uczeń:
- Pisze funkcję testującą i uruchamia ją przez `go test`
- Rozumie konwencje: plik `_test.go`, funkcja `TestXxx(t *testing.T)`
- Pisze test tabelkowy — idiom Go
- Czyta wynik testu i wie, co znaczy `PASS`, `FAIL` i `--- FAIL`

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Napisałeś funkcję liczącą średnią. Skąd wiesz, że działa?"

**Co chcesz usłyszeć:** uruchamiam, patrzę na wynik, sprawdzam w głowie.

**Drugie pytanie:**
> "Za miesiąc coś w niej poprawiasz. Ile razy sprawdzasz ręcznie wszystkie przypadki — zero, jeden, pięć? A gdyby program sam to sprawdzał w sekundę?"

## Krok 2 — Mostek (10 min)
**Mostek:**
> "Test to zwykła funkcja, która wywołuje twój kod i porównuje wynik z oczekiwanym. Go ma to wbudowane — bez instalowania czegokolwiek."

Uczeń tworzy dwa pliki w `kurs/zadania/27-testy/`:

`kalkulator.go`:
```go
package main

func Dodaj(a, b int) int {
	return a + b
}
```

`kalkulator_test.go`:
```go
package main

import "testing"

func TestDodaj(t *testing.T) {
	wynik := Dodaj(2, 3)
	if wynik != 5 {
		t.Errorf("Dodaj(2, 3) = %d, oczekiwano 5", wynik)
	}
}
```

Uruchomienie (uczeń, w katalogu `kurs/zadania`):
```sh
go test ./27-testy
go test -v ./27-testy
```

**Pytania:**
- "Trzy konwencje muszą się zgadzać. Jakie?" → plik kończy się `_test.go`, funkcja zaczyna się `Test`, przyjmuje `t *testing.T`
- "Zmień nazwę funkcji na `SprawdzDodaj` i uruchom ponownie." → test nie zostanie znaleziony
- "Co robi `-v`?" → pokazuje każdy test z osobna, nie tylko podsumowanie
- "Zepsuj funkcję (`a - b`) i uruchom. Przeczytaj komunikat." → widać nazwę testu, plik, linię i twój komunikat

## Krok 3 — Eksperyment (15-20 min)

1. **Dobry komunikat błędu:**
   ```go
   t.Errorf("Dodaj(2, 3) = %d, oczekiwano 5", wynik)   // dobry
   t.Errorf("błąd")                                     // bezużyteczny
   ```
   > "Który komunikat pozwoli ci naprawić kod bez otwierania testu?"
   Konwencja Go: `funkcja(argumenty) = otrzymano, oczekiwano wartość`.
2. **`Errorf` vs `Fatalf`:**
   ```go
   func TestDwa(t *testing.T) {
       t.Errorf("pierwszy problem")
       t.Errorf("drugi problem")     // ten też się wypisze
   }

   func TestTrzy(t *testing.T) {
       t.Fatalf("koniec")
       t.Errorf("tego nie zobaczysz")
   }
   ```
   > "Kiedy chcesz zobaczyć wszystkie problemy, a kiedy przerwać po pierwszym?"
   → `Fatalf`, gdy dalsze sprawdzanie nie ma sensu (np. funkcja zwróciła błąd zamiast wyniku)
3. **Test tabelkowy** — idiom Go:
   ```go
   func TestDodajTabela(t *testing.T) {
       przypadki := []struct {
           nazwa      string
           a, b       int
           oczekiwane int
       }{
           {"dodatnie", 2, 3, 5},
           {"z zerem", 0, 7, 7},
           {"ujemne", -2, -3, -5},
           {"mieszane", -2, 5, 3},
       }

       for _, p := range przypadki {
           t.Run(p.nazwa, func(t *testing.T) {
               wynik := Dodaj(p.a, p.b)
               if wynik != p.oczekiwane {
                   t.Errorf("Dodaj(%d, %d) = %d, oczekiwano %d", p.a, p.b, wynik, p.oczekiwane)
               }
           })
       }
   }
   ```
   > "Co jest tu ze slice'ów (4.1), co ze struktur (7.1), a co z funkcji anonimowych (5.2)?"
   > "Uruchom z `-v`. Jak nazywają się podtesty?" → `TestDodajTabela/dodatnie`
   > "Ile linii dopiszesz przy nowym przypadku?" → jedną
   Uczeń uruchamia jeden podtest: `go test -run TestDodajTabela/ujemne -v ./27-testy`
4. **Testowanie funkcji zwracającej błąd:**
   ```go
   func Podziel(a, b float64) (float64, error) {
       if b == 0 {
           return 0, errors.New("dzielenie przez zero")
       }
       return a / b, nil
   }

   func TestPodziel(t *testing.T) {
       wynik, err := Podziel(10, 2)
       if err != nil {
           t.Fatalf("nieoczekiwany błąd: %v", err)
       }
       if wynik != 5 {
           t.Errorf("Podziel(10,2) = %v, oczekiwano 5", wynik)
       }

       if _, err := Podziel(1, 0); err == nil {
           t.Error("oczekiwano błędu przy dzieleniu przez zero, nie było")
       }
   }
   ```
   > "Testujesz oba scenariusze: udany i nieudany. Który częściej pomijają początkujący?"
5. **Pokrycie kodu:**
   ```sh
   go test -cover ./27-testy
   ```
   > "Ile procent twojego kodu wykonują testy? Czy 100% oznacza brak błędów?"
   → nie. Pokrycie mówi, co zostało **wykonane**, nie co zostało **sprawdzone**.

## Krok 4 — Pogłębienie (10 min)

**Co testować, a czego nie:**
| Kod | Testować? |
| --- | --- |
| Funkcja licząca coś na podstawie argumentów | tak, zawsze |
| Obsługa błędnych danych | tak — tu mieszkają błędy |
| Warunki brzegowe (zero, pusta lista, wartość ujemna) | tak |
| Kod, który tylko wypisuje na ekran | rzadko |
| Biblioteka standardowa | nie, jest przetestowana |

**Nazewnictwo i organizacja:**
- plik `kalkulator.go` → testy w `kalkulator_test.go`, obok
- pliki `_test.go` **nie trafiają** do zbudowanego programu
- `go test ./...` uruchamia testy w całym projekcie

**Przydatne opcje:**
```sh
go test ./...                    # wszystko
go test -v ./27-testy            # szczegółowo
go test -run TestDodaj ./...     # tylko pasujące nazwą
go test -cover ./...             # z pokryciem
go test -race ./...              # z wykrywaniem wyścigów (moduł 11)
```

**Pliki tymczasowe w testach:**
```go
func TestZapis(t *testing.T) {
	katalog := t.TempDir()          // sam się posprząta
	sciezka := filepath.Join(katalog, "test.txt")
	...
}
```
> "`t.TempDir()` tworzy katalog i kasuje go po teście. Nie musisz sprzątać ręcznie."

**`t.Helper()`** — gdy piszesz własną funkcję pomocniczą do sprawdzania:
```go
func sprawdzRowne(t *testing.T, otrzymano, oczekiwano int) {
	t.Helper()      // błędy będą wskazywać linię wywołania, nie wnętrze helpera
	if otrzymano != oczekiwano {
		t.Errorf("otrzymano %d, oczekiwano %d", otrzymano, oczekiwano)
	}
}
```

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "testy". Sugerowane:
- 🔥 Napisz test do funkcji `poleKola` z ćwiczenia 7.2 (uwaga na porównywanie `float64` — z tolerancją, jak w 3.1)
- ⭐ Test tabelkowy do funkcji walidującej wiek: pięć przypadków, w tym brzegowe (0, 150, -1, 151)
- ⚡ Wybierz dowolną własną funkcję z wcześniejszych zadań, napisz do niej testy, potem **celowo zepsuj** funkcję i sprawdź, czy testy to złapały

Kod ucznia: `kurs/zadania/27-testy/`.

## Pułapki
- **Zła nazwa pliku** — bez `_test.go` testy nie zostaną znalezione, i nikt nie powie ani słowa.
- **Zła nazwa funkcji** — `TestDodaj` z wielkiej litery po `Test`; `Testdodaj` nie zadziała.
- **Brak `t *testing.T`** → funkcja nie jest testem.
- **Bezużyteczne komunikaty** (`t.Error("źle")`) — przy 30 testach nie wiadomo, co się stało.
- **Testy zależne od kolejności** — każdy test musi działać samodzielnie. Go może je uruchamiać równolegle.
- **Testowanie na prawdziwych plikach użytkownika** — używaj `t.TempDir()`.
- **`t.Fatalf` w podteście** kończy tylko ten podtest, nie cały test — to zwykle właśnie to, czego chcesz.
- **Porównywanie `float64` przez `!=`** — z 2.2: porównuj z tolerancją.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **`t.Context()`** (1.24) — kontekst anulowany po zakończeniu testu.
- **`t.Chdir(katalog)`** (1.24) — zmiana katalogu roboczego na czas testu, ze sprzątaniem.
- **`b.Loop()`** (1.24) — nowa forma benchmarku zamiast `for i := 0; i < b.N; i++`.
- **`testing/synctest`** (stabilne w 1.25) — testowanie kodu współbieżnego z wirtualnym czasem, bez `time.Sleep` w testach. Wraca w 11.3.
- `go vet` uruchamia się **automatycznie przy `go test`** — więc błędne czasowniki `Printf` z lekcji 2.3 wyjdą tu same.

## Notatki tutora
- **Test tabelkowy to idiom, który uczeń zobaczy w każdym projekcie Go.** Warto poświęcić mu więcej czasu niż pojedynczym testom.
- **Uczeń sam uruchamia `go test`** i wkleja wynik — zasada kursu bez zmian. Agent nie uruchamia kodu.
- Ćwiczenie ⚡ (zepsuj kod, sprawdź czy testy złapały) jest najważniejsze dydaktycznie: pokazuje, **po co** są testy, a nie tylko jak je pisać.
- Jeśli uczeń pyta o biblioteki typu `testify` (`assert.Equal`) — powiedz, że istnieją i są popularne, ale w Go standardem jest zwykły `if` z `t.Errorf`. Bez zależności zewnętrznych.
- Nie wprowadzaj atrap (mocków) ani wstrzykiwania zależności. Poza kursem.
- To dobry moment na quiz obejmujący moduły 5-9 — uczeń ma za sobą najtrudniejszą część.
