# Lekcja 2.1 — Zmienne i typy proste

## Cel
Po lekcji uczeń:
- Tworzy zmienną dwoma sposobami (`var` i `:=`) i wie, kiedy który
- Rozróżnia cztery typy: `int`, `float64`, `string`, `bool`
- Rozumie, że w Go typ zmiennej jest **ustalony na zawsze** w momencie utworzenia
- Zna pojęcie wartości zerowej (`zero value`) i wie, dlaczego Go nie ma "pustej" zmiennej

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Pomyśl o pudełkach w spiżarni. Każde ma naklejkę: 'cukier', 'mąka', 'sól'. Co jest na naklejce, a co w środku? Czy można wymienić zawartość, zostawiając naklejkę?"

**Co chcesz usłyszeć:** naklejka = nazwa, zawartość = wartość, zawartość można podmienić.

**Drugie pytanie — to jest kluczowe dla Go:**
> "A gdyby pudełko z naklejką 'cukier' było **pudełkiem na sypkie**, i fizycznie nie dało się do niego wlać mleka? Dobrze to czy źle?"

**Czego NIE rób:** nie mów jeszcze "zmienna", "typ", "deklaracja".

## Krok 2 — Mostek (10 min)
**Mostek:**
> "To co opisałeś — pudełko z naklejką, przeznaczone na jeden rodzaj zawartości — w Go nazywamy **zmienną**. Naklejka to nazwa, zawartość to wartość, a rodzaj pudełka to **typ**. I tak, w Go pudełko na liczby naprawdę nie przyjmie tekstu."

**Minimalny przykład** — uczeń tworzy `kurs/zadania/02-zmienne/main.go`:

```go
package main

import "fmt"

func main() {
	var cukier int = 5
	fmt.Println(cukier)
}
```

Uruchomienie: `go run ./02-zmienne`

**Pytania:**
- "Które słowo to naklejka, które to zawartość, a które mówi, jakiego rodzaju jest pudełko?"
- "Czemu przy `Println` nie ma cudzysłowów wokół `cukier`?"
  → bo chcemy zawartość pudełka, nie napis "cukier". Niech uczeń spróbuje `fmt.Println("cukier")` i porówna.

Teraz nazwij: **deklaracja zmiennej**, **przypisanie** (`=`), **typ**.

## Krok 3 — Eksperyment (15 min)
Uczeń modyfikuje plik i uruchamia po każdym kroku.

1. `var mleko int = 2` → wypisz. Potem `mleko = 3` (bez `var`!) → wypisz ponownie.
   > "Co się stało ze starą wartością? I czemu za drugim razem nie było `var`?"
2. Spróbuj `mleko = "pełne"`.
   → `cannot use "pełne" (untyped string constant) as int value in assignment`
   > "Wklej mi dokładny komunikat. Co Go ci mówi?"
   To jest ta różnica z kroku 1 — pudełko na liczby nie przyjmie tekstu. **W Go typ jest na stałe.**
3. **Krótszy zapis** — uczeń pisze:
   ```go
   maka := 7
   fmt.Println(maka)
   ```
   > "Gdzie się podziało `var` i gdzie `int`? Skąd Go wie, że to liczba?"
   → z wartości po prawej. To się nazywa **wnioskowanie typu**. `:=` = "utwórz i przypisz".
4. **Cztery typy przez eksperyment** — uczeń dopisuje i wypisuje typ każdej:
   ```go
   wiek := 30
   wzrost := 1.75
   imie := "Anna"
   pelnoletni := true

   fmt.Printf("%T %T %T %T\n", wiek, wzrost, imie, pelnoletni)
   ```
   → `int float64 string bool`
   > "Co Go pokazało? `%T` znaczy 'wypisz typ' — o `Printf` szerzej w 2.3."
5. **Wartość zerowa** — uczeń pisze deklarację bez wartości:
   ```go
   var licznik int
   var nazwa string
   var gotowe bool
   fmt.Println(licznik, nazwa, gotowe)
   ```
   → `0  false` (między `0` a `false` pusty string)
   > "Co jest w pudełku, do którego nic nie włożyłeś? Czy to jest 'nic'?"
   → **W Go nie ma niezainicjowanej zmiennej.** Każdy typ ma swoją wartość zerową: `0`, `""`, `false`.
6. **Nieużywana zmienna** — uczeń dodaje `var niepotrzebna int` i nic z nią nie robi.
   → `declared and not used: niepotrzebna`
   > "To jest **błąd**, nie ostrzeżenie — program się nie skompiluje. Jak myślisz, czemu autorzy Go tak zdecydowali?"

## Krok 4 — Pogłębienie (15 min)

**Konwersje — w Go zawsze jawne:**
```go
wiek := 30           // int
wzrostM := 1.75      // float64

// suma := wiek + wzrostM     // BŁĄD: invalid operation: mismatched types int and float64
suma := float64(wiek) + wzrostM   // OK — jawna konwersja
```
> "Inne języki zamieniłyby to same. Go każe napisać wprost. Co zyskujesz, a co tracisz?"
→ zysk: nigdy nie zgadujesz, co się stało z twoimi danymi. Strata: więcej pisania.

Uczeń próbuje:
- `int(3.9)` → `3` — **obcina, nie zaokrągla!**
- `float64(7) / float64(2)` → `3.5`, ale `7 / 2` (dwa `int`) → `3`
  > "Skąd ta różnica? Dzielenie liczb całkowitych daje liczbę całkowitą."
- `string(65)` → `"A"` (!) — to konwersja kodu znaku, nie liczby na napis. Do zamiany liczby na tekst służy `strconv.Itoa(65)` → `"65"`. Wspomnij, wróci w 2.4.

**Nazewnictwo zmiennych:**
- `camelCase` — `liczbaKotow`, nie `liczba_kotow` (to konwencja Go, `gofmt` jej nie wymusza, ale cały świat Go tak pisze)
- litery, cyfry, `_`; nie zaczynają się od cyfry
- **krótkie nazwy są w Go w porządku** — `i` w pętli, `s` na string, `err` na błąd. Go ceni zwięzłość: im mniejszy zasięg, tym krótsza nazwa
- nie używaj słów kluczowych (`func`, `var`, `if`, `for`, `type`)

**`var` czy `:=`?** Reguła praktyczna dla ucznia:
| Sytuacja | Zapis |
| --- | --- |
| Zwykłe utworzenie zmiennej wewnątrz funkcji | `:=` |
| Chcesz wartość zerową (`0`, `""`, `false`) | `var x int` |
| Chcesz inny typ niż domyślny (np. `float64` dla `2`) | `var x float64 = 2` |
| Poza funkcją (na poziomie pakietu) | `var` — `:=` tam nie działa |

Uczeń próbuje `:=` poza funkcją → `syntax error: non-declaration statement outside function body`.

**Więcej typów liczbowych — pokaż istnienie, nie ucz:**
`int8`, `int16`, `int32`, `int64`, `uint`, `float32`... Uczeń używa `int` i `float64` i tyle. Wróci przy JSON w 9.2.

## Pułapki
- **`=` vs `:=`** — `:=` tworzy nową zmienną, `=` zmienia istniejącą. Użycie `:=` dwa razy na tej samej nazwie w tym samym zasięgu → `no new variables on left side of :=`.
- **`declared and not used`** — najczęstszy błąd początkującego. Go nie pozwala zostawić nieużywanej zmiennej. Obejście na czas eksperymentu: `_ = zmienna`.
- **Dzielenie całkowite** — `7 / 2` to `3`, nie `3.5`. Cichy błąd w obliczeniach, kompilator nic nie powie.
- **`int(3.9)` obcina** — do zaokrąglania jest `math.Round`.
- **Wielkość pierwszej litery ma znaczenie** — `wiek` i `Wiek` to dwie różne zmienne. Wielka litera niesie dodatkowe znaczenie (eksport z pakietu) — dojdziemy w 5.3.
- **Polskie znaki w nazwach działają** (`żółw := 2`) — ale nie używaj. Konwencja: bez ogonków.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **`min(a, b)` i `max(a, b)` są wbudowane** (od 1.21) — nie trzeba `math.Min` (która i tak działa tylko na `float64`). Pokaż na końcu: `fmt.Println(min(3, 7), max(3, 7))`.
- Jeśli w tutorialu uczeń zobaczy `var x int = 5` wszędzie — to nie błąd, po prostu rozwlekle. Idiom to `x := 5`.

## Notatki tutora
- **Nie wprowadzaj slice'ów, map ani struktur** — to moduły 4 i 7. Jeśli uczeń pyta "a jak przechować wiele wartości" → "moduł 4, na razie po jednej".
- **`%T` w `Printf` to narzędzie diagnostyczne** — pokaż jako "gdy nie wiesz, co masz w zmiennej, sprawdź". Uczeń będzie tego używał przez cały kurs.
- Wartość zerowa to jeden z lepszych pomysłów Go — warto podkreślić: **nie ma czegoś takiego jak zmienna z przypadkową zawartością**. To eliminuje całą klasę błędów.
- Jeśli uczeń zna arkusze kalkulacyjne — analogia: komórka sformatowana jako liczba nie przyjmie tekstu jako liczby. Działa dobrze.
