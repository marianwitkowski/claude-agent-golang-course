# Lekcja 2.2 — Operatory i wyrażenia

## Cel
Po lekcji uczeń:
- Używa operatorów arytmetycznych, w tym `%` (reszta z dzielenia)
- Buduje warunki z operatorów porównania i logicznych (`&&`, `||`, `!`)
- Rozumie, że `+` na tekstach skleja, a na różnych typach — nie działa wcale
- Zna `++`, `+=` i wie, że w Go `++` to instrukcja, nie wyrażenie

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Dzielisz 17 cukierków między 5 dzieci po równo. Ile dostanie każde i co ci zostanie w ręce?"

(3 cukierki dla każdego, 2 zostają)

**Drugie pytanie:**
> "Te dwie liczby — 3 i 2 — to wyniki dwóch różnych pytań. Jak byś nazwał każde z nich?"

**Co chcesz usłyszeć:** ile na osobę (dzielenie) i ile zostało (reszta).

## Krok 2 — Mostek (5 min)
**Mostek:**
> "Go ma osobne operatory na oba te pytania. `/` daje ile na osobę, `%` daje ile zostało."

Uczeń tworzy `kurs/zadania/03-operatory/main.go`:

```go
package main

import "fmt"

func main() {
	cukierki := 17
	dzieci := 5

	fmt.Println(cukierki / dzieci) // ile na osobę
	fmt.Println(cukierki % dzieci) // ile zostało
}
```

**Pytanie:** "Zgadza się z tym, co policzyłeś w głowie?"

## Krok 3 — Eksperyment (15 min)

**A. Arytmetyka** — uczeń próbuje po kolei:
1. `+`, `-`, `*` na liczbach całkowitych — bez niespodzianek
2. `17 / 5` → `3`. `17.0 / 5.0` → `3.4`
   > "Ta sama operacja, dwa różne wyniki. Od czego to zależy?"
   → od typu argumentów. Dzielenie dwóch `int` daje `int`.
3. `17 % 5` → `2`. Potem `-17 % 5` → `-2`
   > "Znak reszty idzie za dzielną. Zapamiętaj, przyda się przy sprawdzaniu parzystości."
4. `10 % 2` → `0`, `11 % 2` → `1`
   > "Do czego mógłbyś użyć `% 2`?" → sprawdzanie parzystości. Wróci w module 3.
5. **Dzielenie przez zero** — uczeń próbuje `x := 0; fmt.Println(10 / x)`
   → program się kompiluje, ale przy uruchomieniu: `panic: runtime error: integer divide by zero`
   > "Kompilator tego nie złapał. Kiedy się o tym dowiedziałeś?" → dopiero przy uruchomieniu. To **błąd czasu wykonania**, temat modułu 6.
   (Uwaga: `10 / 0` wprost, ze stałą, **jest** błędem kompilacji — Go liczy stałe podczas kompilacji.)

**B. Tekst:**
6. `"Anna" + " " + "Nowak"` → `Anna Nowak`
   > "`+` na tekstach robi co innego niż na liczbach. Jak byś to nazwał?" → sklejanie (konkatenacja)
7. `"wiek: " + 30` → `invalid operation: mismatched types untyped string and untyped int`
   > "Wklej komunikat. Co Go odmawia zrobienia?"
   → Go **nie zgaduje**. Zamiana liczby na tekst: `strconv.Itoa(30)` albo `fmt.Sprintf` (2.3).

**C. Porównania** — uczeń wypisuje wyniki:
```go
fmt.Println(5 > 3)   // true
fmt.Println(5 == 5)  // true
fmt.Println(5 != 5)  // false
fmt.Println("a" < "b") // true — teksty porównują się alfabetycznie
```
> "Jakiego typu jest wynik porównania?" → `bool`. Sprawdź `%T`.

**D. Logika:**
```go
wiek := 25
maPrawoJazdy := true

fmt.Println(wiek >= 18 && maPrawoJazdy) // true — oba muszą być prawdą
fmt.Println(wiek < 18 || maPrawoJazdy)  // true — wystarczy jedno
fmt.Println(!maPrawoJazdy)              // false — odwrócenie
```
> "Powiedz po polsku, co znaczy każda z trzech linii."

## Krok 4 — Pogłębienie (10-15 min)

**Skróty przypisania:**
```go
licznik := 0
licznik = licznik + 1  // długo
licznik += 1           // krócej
licznik++              // najkrócej
```
Działają też `-=`, `*=`, `/=`, `%=` i `--`.

**Pułapka wyjątkowa dla Go** — uczeń próbuje:
```go
// x := licznik++          // BŁĄD: syntax error
// fmt.Println(licznik++)  // BŁĄD
```
> "W wielu językach `++` można wstawić w środek wyrażenia. Go nie pozwala. `licznik++` to **osobna instrukcja**, sama w linii. Zgadujesz, dlaczego autorzy tak zdecydowali?"
→ bo `a[i++] = i++` w innych językach to koszmar do czytania. Go usuwa problem, usuwając możliwość.

**Nie ma `++x`** (przed zmienną) — tylko `x++`.

**Kolejność działań** — jak w szkole: `*`, `/`, `%` przed `+` i `-`; porównania po arytmetyce; `&&` przed `||`.
```go
fmt.Println(2 + 3*4)     // 14, nie 20
fmt.Println((2 + 3) * 4) // 20
```
**Rada praktyczna:** w wątpliwości daj nawiasy. Kosztują dwa znaki, oszczędzają godzinę debugowania.

**Skrócone obliczanie (`short-circuit`)** — uczeń sprawdza:
```go
dzielnik := 0
if dzielnik != 0 && 10/dzielnik > 1 {
	fmt.Println("ok")
}
```
> "Czemu to nie wybuchło dzieleniem przez zero?"
→ bo `&&` przerywa po pierwszym `false` i drugiej części w ogóle nie liczy. To bardzo częsty wzorzec zabezpieczający.

**Czego w Go NIE ma** (uczeń może szukać, bo widział gdzieś indziej):
- operatora potęgowania `**` → jest `math.Pow(2, 10)`
- operatora trójargumentowego `warunek ? a : b` → jest zwykły `if` (moduł 3)

**Bity** — `&`, `|`, `^`, `<<`, `>>` istnieją. Wspomnij jednym zdaniem, nie ucz.

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "operatory". Sugerowane:
- 🔥 Kalkulator: dwie liczby w zmiennych, wypisz sumę, różnicę, iloczyn, iloraz i resztę
- ⭐ Sekundy na czas: `sekundy := 3725` → wypisz "1 h 2 min 5 s" (wymusi `/` i `%`)
- ⚡ Trzy zmienne `bool` (`maBilet`, `jestPelnoletni`, `maZnizke`) — jednym wyrażeniem logicznym sprawdź, czy wpuszczamy na koncert; opisz warunek słowami przed napisaniem kodu

## Pułapki
- **Dzielenie całkowite po cichu ucina** — `procent := 50 / 100` daje `0`, nie `0.5`. To najczęstszy cichy błąd początkującego w Go.
- **`%` nie działa na `float64`** → `invalid operation: operator % not defined on float64`. Do tego jest `math.Mod`.
- **`=` vs `==`** — w Go pomyłka rzadko przechodzi (`if x = 5` to błąd składni), więc jest lżej niż w innych językach. Ale warto nazwać różnicę.
- **`&&` to nie `&`** — `&` to operacja na bitach. Jedno `&` w warunku daje dziwne wyniki albo błąd typów.
- **Porównywanie `float64`** — `0.1 + 0.2 == 0.3` → `false`. Liczby zmiennoprzecinkowe są przybliżeniami. Niech uczeń to zobaczy i zapamięta: nie porównuj `float64` przez `==`.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- `min(a, b)`, `max(a, b)` wbudowane (1.21) — działają na dowolnej liczbie argumentów: `min(3, 7, 2)`.
- `cmp.Or(a, b)` (1.22) — zwraca pierwszą niezerową wartość, przydatne na wartości domyślne. Wspomnij, nie ćwicz.

## Notatki tutora
- **`%` warto przećwiczyć więcej niż resztę operatorów** — wraca przy parzystości (moduł 3), przy formatowaniu czasu, przy losowaniu. Jeśli masz 5 dodatkowych minut, wydaj je tutaj.
- Gdy uczeń pyta "a jak podnieść do potęgi" — `math.Pow(2, 10)`, ale zwraca `float64`. To dobry moment na przypomnienie o konwersjach z 2.1.
- **Nie tłumacz operacji bitowych.** Jeśli uczeń natknie się na `<<` w cudzym kodzie, powiedz "to operacje na bitach, na tym etapie ich nie potrzebujesz".
- Eksperyment z dzieleniem przez zero jest wartościowy — po raz pierwszy uczeń widzi błąd, którego kompilator nie łapie. To zapowiedź modułu 6, warto nazwać: "kompilator sprawdza kształt kodu, nie przewidzi wszystkich danych".
