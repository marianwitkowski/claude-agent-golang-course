# Lekcja 4.4 — `range`

## Cel
Po lekcji uczeń:
- Iteruje po slice i mapie przez `for ... range`
- Świadomie wybiera, czy potrzebuje indeksu, wartości, czy obu
- Wie, że `range` po slice daje **kopię** wartości — i co z tego wynika
- Umie wypisać mapę w stałej, posortowanej kolejności

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Czytasz na głos listę zakupów. Mówisz 'pozycja pierwsza: chleb, pozycja druga: mleko' czy po prostu 'chleb, mleko'? Kiedy numery są potrzebne, a kiedy zawadzają?"

**Co chcesz usłyszeć:** numery przydają się, gdy o nich rozmawiamy ("skreśl trzecią"); przy zwykłym czytaniu są zbędne.

## Krok 2 — Mostek (10 min)
**Mostek:**
> "Pętla z lekcji 4.1 zawsze dawała ci numer, a wartość musiałeś wyjmować sam. `range` daje jedno i drugie — a ty bierzesz to, czego potrzebujesz."

Uczeń tworzy `kurs/zadania/12-range/main.go`:

```go
package main

import "fmt"

func main() {
	zakupy := []string{"chleb", "mleko", "masło"}

	// klasycznie — z lekcji 4.1
	for i := 0; i < len(zakupy); i++ {
		fmt.Println(i, zakupy[i])
	}

	// z range
	for i, produkt := range zakupy {
		fmt.Println(i, produkt)
	}
}
```

**Pytania:**
- "Ten sam wynik. Co zniknęło z zapisu?" → `len`, warunek, zwiększanie licznika, `zakupy[i]`
- "`i` i `produkt` — skąd Go wie, co ma być w której zmiennej?" → kolejność jest ustalona: **najpierw indeks, potem wartość**
- "Możesz je nazwać inaczej?" → tak, to zwykłe zmienne. Konwencja: `i` na indeks, sensowna nazwa na wartość.

## Krok 3 — Eksperyment (15 min)

1. **Sama wartość** — uczeń usuwa `i`:
   ```go
   for _, produkt := range zakupy {
       fmt.Println(produkt)
   }
   ```
   > "Co robi podkreślnik? Spróbuj napisać `i`, ale go nie użyć."
   → `declared and not used: i`. `_` to "wiem, że tu coś jest, świadomie ignoruję".
2. **Sam indeks:**
   ```go
   for i := range zakupy {
       fmt.Println(i)
   }
   ```
   > "Kiedy potrzebujesz numeru, ale nie wartości?" → gdy chcesz zmieniać elementy (za chwilę)
3. **`range` po mapie:**
   ```go
   punkty := map[string]int{"Anna": 10, "Piotr": 7, "Ewa": 12}

   for imie, p := range punkty {
       fmt.Printf("%s: %d\n", imie, p)
   }
   ```
   > "Przy slice pierwsza zmienna to indeks. A tutaj?" → **klucz**. Druga to wartość.
   > "Uruchom trzy razy. Ta sama kolejność?" → nie. To ta losowość z 4.3.
4. **Pułapka: `range` daje kopię** — najważniejszy eksperyment:
   ```go
   liczby := []int{1, 2, 3}

   for _, v := range liczby {
       v = v * 10           // zmieniamy kopię
   }
   fmt.Println(liczby)      // [1 2 3] — bez zmian!

   for i := range liczby {
       liczby[i] = liczby[i] * 10   // zmieniamy przez indeks
   }
   fmt.Println(liczby)      // [10 20 30]
   ```
   > "Pierwsza pętla nic nie zmieniła. Czemu?"
   → `v` to **kopia** elementu, nie sam element. Żeby zmienić slice, sięgaj przez indeks.
   > "To odwrotnie niż przy przypisaniu slice'a z 4.2, gdzie kopia zmieniała oryginał. Zapamiętaj obie sytuacje."
5. **`range` po tekście** — ostrożnie:
   ```go
   for i, znak := range "Gołąb" {
       fmt.Println(i, string(znak))
   }
   ```
   > "Przyjrzyj się indeksom. Czy idą 0,1,2,3,4?" → nie: 0,1,2,4,6 — bo `ł` i `ą` zajmują po 2 bajty.
   `range` po tekście idzie **po znakach**, ale indeksy są bajtowe. Więcej nie potrzebujesz.
6. **Mapa w stałej kolejności** — rozwiązanie problemu z 4.3:
   ```go
   import ("maps"; "slices")

   for _, imie := range slices.Sorted(maps.Keys(punkty)) {
       fmt.Printf("%s: %d\n", imie, punkty[imie])
   }
   ```
   > "Uruchom kilka razy. Teraz kolejność jest stała. Co dokładnie zrobiliśmy?"
   → wzięliśmy klucze, posortowaliśmy je, i po posortowanej liście sięgamy do mapy.

## Krok 4 — Pogłębienie (10 min)

**Wszystkie formy `range` w jednej tabeli:**
| Zapis | Po slice | Po mapie |
| --- | --- | --- |
| `for i, v := range x` | indeks, wartość | klucz, wartość |
| `for i := range x` | indeks | **klucz** (nie wartość!) |
| `for _, v := range x` | wartość | wartość |
| `for range x` | tylko powtarza | tylko powtarza |

> "Uwaga na drugi wiersz: przy mapie `for k := range m` daje **klucze**. Częsty błąd polega na oczekiwaniu wartości."

**`range` po liczbie** (z 3.3) to ta sama konstrukcja: `for i := range 5`.

**Zmiana mapy podczas iteracji** — uczeń próbuje:
```go
for k := range punkty {
	delete(punkty, k)      // usuwanie w trakcie: dozwolone
}
```
Usuwanie w trakcie jest bezpieczne. **Dodawanie** w trakcie — nie: nowy wpis może, ale nie musi zostać odwiedzony. Zasada: nie dodawaj do mapy, po której właśnie iterujesz.

**Kiedy klasyczna pętla, a kiedy `range`:**
| Sytuacja | Wybierz |
| --- | --- |
| Przejście przez wszystkie elementy | `range` |
| Co drugi element, od końca, z przeskokami | klasyczny `for` |
| Iteracja po mapie | `range` (nie ma innej opcji) |
| Powtórzenie N razy | `for i := range N` |

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "range". Sugerowane:
- 🔥 Slice imion — wypisz każde z numerem porządkowym od 1
- ⭐ Mapa produkt→cena: wypisz alfabetycznie po nazwie i policz sumę wszystkich cen
- ⚡ Weź slice liczb i zbuduj z niego mapę `liczba → ile razy wystąpiła`, potem wypisz tylko te, które wystąpiły więcej niż raz

Kod ucznia: `kurs/zadania/12-range/`.

## Pułapki
- **Zmiana `v` w `for _, v := range` nic nie robi** — to kopia. Najczęstsza pułapka `range`.
- **`for k := range mapa` daje klucze, nie wartości** — mylące, jeśli przenosisz nawyk ze slice'ów.
- **Kolejność mapy jest losowa** — jeśli test raz przechodzi, a raz nie, to prawdopodobnie to.
- **Dodawanie do mapy w trakcie iteracji** — nieprzewidywalne.
- **Indeksy przy `range` po tekście przeskakują** dla znaków spoza ASCII.
- **`range` na `nil` slice ani na `nil` mapie nie wybucha** — po prostu zero obiegów. To wygodne i celowe.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **Zmienna pętli jest nowa w każdym obiegu** (1.22) — dotyczy też `range`. Do 1.21 `v` było jedną zmienną nadpisywaną w kółko, co psuło funkcje i goroutine tworzone w pętli. Wróci w 5.2 i 11.1.
- **`for x := range funkcja`** (1.23, iteratory) — `slices.All(s)`, `maps.Keys(m)` zwracają właśnie takie funkcje. Uczeń użył `maps.Keys` w eksperymencie 6, nie musi rozumieć mechanizmu. Jeśli zapyta: "to funkcja, która podaje elementy jedna po drugiej".
- `slices.Sorted(maps.Keys(m))` to dziś standardowy sposób na uporządkowane wypisanie mapy. Wcześniej trzeba było ręcznie zbierać klucze do slice'a i wołać `sort.Strings`.

## Notatki tutora
- **Eksperyment 4 (kopia) jest obowiązkowy.** Uczeń, który go nie zobaczy, napisze pętlę "modyfikującą" slice i spędzi godzinę, nie rozumiejąc, czemu nic się nie dzieje.
- Warto zestawić dwie rzeczy, które wyglądają sprzecznie: przypisanie slice'a **dzieli** dane (4.2), a `range` **kopiuje** wartość (4.4). Różnica: tam kopiowaliśmy uchwyt do magazynu, tu kopiujemy pojedynczy element.
- Nie tłumacz iteratorów (`iter.Seq`). `maps.Keys` uczeń używa jak gotowego narzędzia.
- Jeśli uczeń ma dość kolekcji po czterech lekcjach — to normalne. Moduł 4 jest najbardziej "technicznym" fragmentem kursu. Powiedz, że moduł 5 (funkcje) jest inny i przyjemniejszy.
- To dobry moment na małe podsumowanie: uczeń umie już przechowywać dane (moduł 4), decydować (3) i liczyć (2). Warto to nazwać.
