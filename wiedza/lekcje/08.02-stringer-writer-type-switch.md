# Lekcja 8.2 — `Stringer`, `io.Writer`, `any` i `switch` po typach

## Cel
Po lekcji uczeń:
- Implementuje `fmt.Stringer` i widzi, jak zmienia sposób wypisywania jego typu
- Rozumie, czym jest `io.Writer`, i pisze funkcję zapisującą "gdziekolwiek"
- Wyciąga konkretny typ z `any` przez asercję i `switch` po typach
- Wie, kiedy `any` jest uzasadnione, a kiedy jest lenistwem

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Piszesz coś długopisem. Ta sama czynność — a podłoże może być kartką, tablicą, ekranem dotykowym. Czy ręka wie, na czym pisze?"

**Drugie pytanie:**
> "Napisałeś raport. Chcesz go: wyświetlić na ekranie, zapisać do pliku, wysłać przez sieć. Ile razy musisz napisać kod tworzący ten raport?"

→ raz, jeśli "gdzie pisać" jest parametrem.

## Krok 2 — Mostek (10 min)
**Mostek:**
> "Go ma na to jeden interfejs: `io.Writer`. Ma jedną metodę — 'zapisz te bajty'. Ekran, plik, sieć, bufor w pamięci — wszystkie ją mają."

Uczeń tworzy `kurs/zadania/23-writer/main.go`:

```go
package main

import (
	"fmt"
	"os"
	"strings"
)

func raport(w io.Writer, imie string) {
	fmt.Fprintf(w, "Raport dla: %s\n", imie)
	fmt.Fprintln(w, "Wszystko w porządku.")
}

func main() {
	raport(os.Stdout, "Anna")        // na ekran

	var bufor strings.Builder
	raport(&bufor, "Piotr")          // do pamięci
	fmt.Println("zebrane:", bufor.String())
}
```
(uczeń dopisuje import `"io"`)

**Pytania:**
- "`fmt.Fprintf` — czym różni się od `fmt.Printf`?" → ma dodatkowy pierwszy argument: **dokąd** pisać
- "Ile razy napisaliśmy treść raportu?" → raz
- "`os.Stdout` i `&bufor` to zupełnie różne rzeczy. Co je łączy?" → obie mają metodę `Write`
- "Czemu `&bufor`, a nie `bufor`?" → bo `Write` ma odbiornik wskaźnikowy (pułapka z 8.1)

## Krok 3 — Eksperyment (15 min)

1. **Do pliku** — zapowiedź modułu 9:
   ```go
   plik, err := os.Create("raport.txt")
   if err != nil {
       fmt.Println("błąd:", err)
       return
   }
   defer plik.Close()

   raport(plik, "Ewa")
   ```
   > "Ta sama funkcja `raport`, trzecie miejsce docelowe, zero zmian w jej kodzie. Zauważ `defer` z 5.3."
2. **`fmt.Stringer`** — jak typ opisuje sam siebie:
   ```go
   type Osoba struct {
       Imie string
       Wiek int
   }

   fmt.Println(Osoba{"Anna", 30})   // {Anna 30}

   func (o Osoba) String() string {
       return fmt.Sprintf("%s (%d l.)", o.Imie, o.Wiek)
   }

   fmt.Println(Osoba{"Anna", 30})   // Anna (30 l.)
   ```
   > "Nie zmieniliśmy `Println`. Skąd wie o naszej metodzie?"
   → `fmt` sprawdza, czy wartość spełnia interfejs `Stringer` (`String() string`). Jeśli tak — używa go.
   > "Gdzie widziałeś ten sam mechanizm?" → `error` z metodą `Error()` (6.1)
3. **Asercja typu** — wyciąganie konkretu:
   ```go
   var x any = "tekst"

   s := x.(string)          // wierzę, że to string
   fmt.Println(s, len(s))

   // n := x.(int)          // panic: interface conversion: interface {} is string, not int

   n, ok := x.(int)         // bezpieczna forma
   fmt.Println(n, ok)       // 0 false
   ```
   > "Znasz zapis `wartosc, ok`. Skąd?" → mapa (4.3). Ten sam wzorzec, trzeci raz w kursie.
4. **`switch` po typach** — obiecany w 3.2:
   ```go
   func opisz(x any) string {
       switch v := x.(type) {
       case int:
           return fmt.Sprintf("liczba całkowita: %d", v)
       case string:
           return fmt.Sprintf("tekst o długości %d", len(v))
       case bool:
           return fmt.Sprintf("wartość logiczna: %t", v)
       case []int:
           return fmt.Sprintf("slice %d liczb", len(v))
       case nil:
           return "nic"
       default:
           return fmt.Sprintf("nieznany typ %T", v)
       }
   }

   fmt.Println(opisz(42), opisz("ala"), opisz(true), opisz(3.14))
   ```
   > "`v := x.(type)` — czym `v` jest w gałęzi `case int`, a czym w `case string`?" → w każdej gałęzi ma **inny, konkretny** typ
   > "Ten zapis działa tylko w `switch`. Poza nim jest błędem składni."
5. **Praktyczne użycie: `errors.As` z modułu 6.2** — teraz uczeń rozumie mechanizm:
   ```go
   type BladWalidacji struct{ Pole, Powod string }
   func (b *BladWalidacji) Error() string { return b.Pole + ": " + b.Powod }

   err := fmt.Errorf("zapis: %w", &BladWalidacji{Pole: "wiek", Powod: "ujemny"})

   var bw *BladWalidacji
   if errors.As(err, &bw) {
       fmt.Println("problem z polem:", bw.Pole)
   }
   ```
   > "`errors.As` robi to samo, co asercja typu, tylko zagląda też do opakowanych błędów."

## Krok 4 — Pogłębienie (10 min)

**`io.Writer` i `io.Reader` — dwa filary biblioteki standardowej:**
```go
type Writer interface { Write(p []byte) (n int, err error) }
type Reader interface { Read(p []byte) (n int, err error) }
```
> "Jedna metoda każdy. Dzięki nim `bufio.Scanner` z lekcji 2.4 potrafi czytać zarówno z klawiatury, jak i z pliku, i z sieci — bez żadnej wiedzy, skąd dane przychodzą."

Uczeń łączy to z 2.4:
```go
czytnik := bufio.NewScanner(os.Stdin)              // klawiatura
czytnik2 := bufio.NewScanner(strings.NewReader("a\nb\nc"))   // tekst w pamięci
```
> "Ten sam `Scanner`, inne źródło. To jest zysk z interfejsów."

**Kiedy `any` jest uzasadnione:**
| Sytuacja | Werdykt |
| --- | --- |
| Funkcja jak `fmt.Println`, przyjmująca cokolwiek do wypisania | uzasadnione |
| Dane z JSON o nieznanej strukturze (moduł 9) | uzasadnione |
| "Nie chce mi się wymyślać typu" | lenistwo |
| Funkcja liczbowa mająca działać na `int` i `float64` | generyki, nie `any` |

**Uwaga o kolejności w `switch` po typach:** gałęzie sprawdzane są od góry. Jeśli jedna z nich to interfejs (np. `case error:`), złapie wszystkie typy go spełniające — dawaj takie gałęzie **na końcu**.

## Pułapki
- **Asercja bez `, ok`** → panika przy złym typie. Zawsze `v, ok := x.(T)`, chyba że masz absolutną pewność.
- **`String()` wywołujące `fmt.Sprintf("%v", o)` na własnym typie** → nieskończona rekurencja i przepełnienie stosu. W metodzie `String` używaj `%v` tylko na **polach**, nie na całej strukturze.
- **`String()` z odbiornikiem wskaźnikowym, wypisywanie wartości** — `fmt.Println(o)` nie użyje metody, bo `Osoba` jej nie ma (ma `*Osoba`). Ta sama pułapka co w 8.1.
- **`x.(type)` poza `switch`** → błąd składni.
- **`any` jako sposób na ominięcie systemu typów** — kompilator przestaje pomagać, błędy przenoszą się na czas wykonania.
- **Zapomniany `defer plik.Close()`** — dane mogą nie trafić na dysk. Więcej w module 9.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
- **`any`** to alias na `interface{}` od 1.18 — pisz `any`.
- `errors.AsType[T](err)` (1.26) jest czytelniejszą wersją `errors.As`; opiera się na tym samym mechanizmie asercji typu.
- W module 9 uczeń zobaczy `os.Root` (1.24) — ograniczony dostęp do katalogu; jego metody zwracają zwykłe `io.Reader`/`io.Writer`, więc cała wiedza z tej lekcji działa.

## Notatki tutora
- **`io.Writer` to najlepszy praktyczny przykład wartości interfejsów.** Eksperyment "ta sama funkcja, trzy miejsca docelowe" przekonuje bardziej niż jakiekolwiek wyjaśnienie.
- **`Stringer` jest satysfakcjonujący** — uczeń dodaje jedną metodę i jego typ nagle "ładnie się wypisuje". Dobry moment na zastrzyk motywacji przed modułem 9.
- **Nie przeciągaj `switch` po typach.** To narzędzie używane rzadko; uczeń ma je rozpoznać i rozumieć `errors.As`, nie budować na nim architektury.
- Jeśli uczeń chce pisać funkcje na `any` zamiast konkretnych typów — zatrzymaj. Powiedz: "kompilator to twój darmowy recenzent; `any` go wyłącza".
- To ostatnia lekcja "języka jako takiego". Od modułu 9 kurs schodzi na praktykę: pliki, dane, testy. Warto to nazwać — uczeń zasłużył na poczucie przełomu.
