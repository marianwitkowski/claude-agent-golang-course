# Lekcja 9.3 — Argumenty wiersza poleceń

## Cel
Po lekcji uczeń:
- Czyta argumenty przez `os.Args` i rozumie, co jest pod indeksem 0
- Definiuje opcje przez pakiet `flag` i dostaje pomoc (`-h`) za darmo
- Pisze program użyteczny bez pytania o nic w trakcie działania
- Kończy program właściwym kodem wyjścia

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Twój program z lekcji 2.4 pytał 'jak masz na imię?' i czekał. A teraz wyobraź sobie, że chcesz go uruchomić tysiąc razy w nocy, automatycznie. Co przeszkadza?"

**Co chcesz usłyszeć:** ktoś musi siedzieć i odpowiadać.

**Drugie pytanie:**
> "Jak uruchamiasz komendy, których używałeś w kursie — `go run ./01-hello`, `gofmt -w plik.go`? Czy one o coś pytają?"

→ nie. Wszystko dostają od razu, przy uruchomieniu.

## Krok 2 — Mostek (5-10 min)
**Mostek:**
> "To, co piszesz po nazwie programu, trafia do niego jako lista tekstów. Najprostszy dostęp: `os.Args`."

Uczeń tworzy `kurs/zadania/26-cli/main.go`:

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	fmt.Println(os.Args)
	fmt.Println("liczba argumentów:", len(os.Args))
}
```

Uruchomienie:
```sh
go run ./26-cli
go run ./26-cli ala ma kota
```

**Pytania:**
- "Co jest pod `os.Args[0]`?" → ścieżka do programu, nie pierwszy argument
- "Więc pierwszy prawdziwy argument to?" → `os.Args[1]`
- "Ile wynosi `len(os.Args)` przy uruchomieniu bez argumentów?" → 1
- "Co się stanie przy `os.Args[1]` bez podania argumentu?" → `index out of range` (4.1). **Zawsze sprawdzaj `len` przed sięgnięciem.**

## Krok 3 — Eksperyment (15 min)

1. **Program z wymaganym argumentem:**
   ```go
   if len(os.Args) < 2 {
       fmt.Fprintln(os.Stderr, "użycie: program <nazwa-pliku>")
       os.Exit(1)
   }
   nazwa := os.Args[1]
   fmt.Println("przetwarzam:", nazwa)
   ```
   > "Czemu `os.Stderr`, a nie zwykły `Println`?" → komunikaty o błędach idą na wyjście błędów, żeby nie mieszały się z wynikiem
   > "Co robi `os.Exit(1)`?" → kończy program z kodem błędu; `0` znaczy sukces. Skrypty uruchamiające twój program to sprawdzają.
   > "Uwaga: `os.Exit` **pomija `defer`** (z 6.3). Dlatego używaj go tylko w `main`."
2. **Pakiet `flag` — opcje z nazwami:**
   ```go
   import "flag"

   func main() {
       plik := flag.String("plik", "dane.txt", "ścieżka do pliku wejściowego")
       liczba := flag.Int("n", 10, "ile linii wypisać")
       gadatliwy := flag.Bool("v", false, "więcej komunikatów")

       flag.Parse()

       fmt.Println(*plik, *liczba, *gadatliwy)
   }
   ```
   Uczeń uruchamia:
   ```sh
   go run ./26-cli -plik raport.txt -n 5 -v
   go run ./26-cli -h
   go run ./26-cli
   ```
   > "Skąd wzięła się pomoc przy `-h`?" → `flag` zbudował ją z opisów, które podałeś
   > "Co się wypisało przy uruchomieniu bez argumentów?" → wartości domyślne
   > "Czemu `*plik`, a nie `plik`?" → `flag.String` zwraca **wskaźnik** (7.2); wartość pojawia się dopiero po `flag.Parse()`
3. **Argumenty pozostałe po opcjach:**
   ```go
   flag.Parse()
   pozostale := flag.Args()
   fmt.Println("pliki do przetworzenia:", pozostale)
   ```
   ```sh
   go run ./26-cli -v plik1.txt plik2.txt
   ```
   > "To wzorzec, który znasz z prawdziwych narzędzi: najpierw opcje, potem lista plików."
4. **Prawdziwy program** — uczeń łączy z 9.1:
   ```go
   func main() {
       linie := flag.Int("n", 10, "ile pierwszych linii wypisać")
       flag.Parse()

       if flag.NArg() < 1 {
           fmt.Fprintln(os.Stderr, "użycie: glowa [-n N] <plik>")
           os.Exit(1)
       }

       plik, err := os.Open(flag.Arg(0))
       if err != nil {
           fmt.Fprintln(os.Stderr, "nie mogę otworzyć:", err)
           os.Exit(1)
       }
       defer plik.Close()

       skaner := bufio.NewScanner(plik)
       for i := 0; i < *linie && skaner.Scan(); i++ {
           fmt.Println(skaner.Text())
       }
   }
   ```
   > "Właśnie napisałeś odpowiednik systemowego `head`. Sprawdź na własnym pliku."
   > "Zwróć uwagę na warunek pętli: dwa warunki połączone `&&` (2.2). Który sprawdza się pierwszy?"
5. **Zbudowanie prawdziwego narzędzia:**
   ```sh
   go build -o glowa ./26-cli
   ./glowa -n 3 dane.txt
   ```
   > "Masz plik, który działa bez Go. Możesz go skopiować koledze."
   Po eksperymencie uczeń kasuje binarkę.

## Krok 4 — Pogłębienie (10 min)

**Konwencje narzędzi wiersza poleceń:**
| Zasada | Dlaczego |
| --- | --- |
| Wynik na `os.Stdout`, błędy na `os.Stderr` | żeby dało się przekierować wynik do pliku |
| Kod wyjścia `0` = sukces, `≠0` = błąd | skrypty i CI to sprawdzają |
| `-h` pokazuje pomoc | `flag` daje za darmo |
| Bez argumentów: pomoc lub sensowne domyślne | nie milcz |
| Czytaj z `os.Stdin`, gdy nie podano pliku | pozwala łączyć programy potokiem |

Uczeń sprawdza rozdzielenie strumieni:
```sh
./glowa -n 3 dane.txt > wynik.txt        # wynik do pliku
./glowa -n 3 nie-ma.txt > wynik.txt      # błąd nadal widać na ekranie
```

**Zmienne środowiskowe** — drugi kanał konfiguracji:
```go
klucz := os.Getenv("API_KEY")
if klucz == "" {
	klucz = "domyslny"
}
```
```sh
API_KEY=tajne go run ./26-cli
```
> "Kiedy zmienna środowiskowa jest lepsza od opcji?" → dla sekretów (nie widać ich w historii poleceń) i dla ustawień stałych dla całego środowiska

**Podkomendy** (`git commit`, `go build`) — `flag` sam tego nie robi:
```go
switch os.Args[1] {
case "dodaj": ...
case "lista": ...
}
```
> "Da się ręcznie, ale przy większych narzędziach ludzie sięgają po bibliotekę `cobra`. To temat na moduł 12."

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "argumenty CLI". Sugerowane:
- 🔥 Program przyjmujący imię jako argument i wypisujący powitanie; przy braku argumentu — komunikat o użyciu i kod wyjścia 1
- ⭐ Kalkulator: `./kalk -op dodaj 3 5`, obsłuż cztery działania i błędne dane
- ⚡ Narzędzie `licz`: liczy linie/słowa/znaki w pliku podanym argumentem; opcje `-l`, `-w`, `-c` wybierają, co pokazać; bez opcji pokazuje wszystko; bez pliku czyta ze standardowego wejścia

Kod ucznia: `kurs/zadania/26-cli/`.

## Pułapki
- **`os.Args[1]` bez sprawdzenia `len`** → `index out of range` przy uruchomieniu bez argumentów.
- **`os.Args[0]` to nazwa programu**, nie pierwszy argument.
- **Zapomniany `flag.Parse()`** → wszystkie opcje mają wartości domyślne, cicho i bez błędu.
- **Użycie wartości opcji przed `flag.Parse()`** → wartość domyślna. Kolejność ma znaczenie.
- **Brak `*` przy odczycie opcji** → wypisze adres zamiast wartości. Kompilator to zwykle łapie na niezgodności typów.
- **Definiowanie opcji po `Parse()`** → panika.
- **Błędy na `os.Stdout`** — psuje przekierowanie wyniku do pliku.
- **`os.Exit` pomija `defer`** — pliki mogą zostać niezamknięte, bufory niezapisane. W `main` najpierw sprzątaj, potem wychodź.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
Pakiet `flag` jest niezmieniony od lat i wystarcza do większości narzędzi. Nowości okołonarzędziowe:
- `go build` z `GOOS`/`GOARCH` pozwala zbudować narzędzie na inny system jedną komendą (moduł 12.3).
- W ekosystemie standardem dla rozbudowanych narzędzi jest `spf13/cobra` (podkomendy, autouzupełnianie) — moduł 12.4.

## Notatki tutora
- **Eksperyment 4 (własny `head`) jest bardzo satysfakcjonujący** — uczeń pisze narzędzie, którego odpowiednik ma w systemie. Warto to nazwać.
- **Nie wprowadzaj `cobra`.** `flag` w zupełności wystarcza i jest w bibliotece standardowej.
- Rozdzielenie `Stdout`/`Stderr` jest łatwe do pokazania (przekierowanie do pliku) i uczy myślenia o programie jako o klocku w większym systemie.
- Jeśli uczeń pyta o kolorowanie wyjścia albo paski postępu — powiedz, że to biblioteki zewnętrzne, i wróć do tematu.
- To ostatnia lekcja modułu 9. Uczeń ma teraz komplet do napisania prawdziwego narzędzia: argumenty, pliki, JSON, błędy. Moduł 10 doda testy i porządek w projekcie.
