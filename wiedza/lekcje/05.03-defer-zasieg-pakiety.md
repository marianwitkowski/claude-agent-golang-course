# Lekcja 5.3 — `defer`, zasięg, własny pakiet

## Cel
Po lekcji uczeń:
- Używa `defer` do sprzątania i rozumie kolejność wykonania
- Rozumie zasięg zmiennej: blok, funkcja, pakiet
- Rozpoznaje przesłanianie (`shadowing`) i wie, czemu bywa groźne
- Dzieli program na dwa pliki i wie, co robi wielka litera w nazwie

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Wychodząc z pokoju hotelowego trzeba zgasić światło i zamknąć drzwi. Kiedy to robisz — od razu po wejściu, czy na końcu? A kiedy o tym **postanawiasz**?"

**Co chcesz usłyszeć:** wykonuję na końcu, ale postanawiam od razu (albo wcale nie pamiętam).

**Drugie pytanie:**
> "Gdybyś mógł powiedzieć sobie przy wejściu 'przy wyjściu zgaś światło' i mieć pewność, że to się stanie — nawet gdybyś wychodził w pośpiechu przez okno?"

## Krok 2 — Mostek (10 min)
**Mostek:**
> "Go ma dokładnie to: `defer`. Piszesz na początku, wykonuje się przy wyjściu z funkcji — **zawsze**, którymkolwiek `return` byś wyszedł."

Uczeń tworzy `kurs/zadania/15-defer/main.go`:

```go
package main

import "fmt"

func praca() {
	fmt.Println("wchodzę")
	defer fmt.Println("gaszę światło")
	fmt.Println("pracuję")
}

func main() {
	praca()
	fmt.Println("po wyjściu")
}
```

**Pytania:**
- "W jakiej kolejności się wypisało? Zgadza się z kolejnością w kodzie?"
- "Kiedy wykonała się linia z `defer`?" → tuż przed wyjściem z `praca()`
- "Dopisz `return` między `defer` a `pracuję`. Czy 'gaszę światło' nadal się wypisze?" → tak

## Krok 3 — Eksperyment (15 min)

1. **Kilka `defer` — kolejność odwrotna:**
   ```go
   func kolejnosc() {
       defer fmt.Println("pierwszy defer")
       defer fmt.Println("drugi defer")
       defer fmt.Println("trzeci defer")
       fmt.Println("koniec ciała")
   }
   ```
   > "W jakiej kolejności? Czemu odwrotnie?"
   → jak stos talerzy: ostatni położony zdejmowany pierwszy. Ma to sens przy sprzątaniu: otwierasz plik, potem połączenie — zamykasz w odwrotnej kolejności.
2. **`defer` a `panic`** — uczeń sprawdza, czy sprzątanie działa też przy awarii:
   ```go
   func awaria() {
       defer fmt.Println("i tak posprzątam")
       liczby := []int{1, 2}
       fmt.Println(liczby[5])   // panic
   }
   ```
   > "Program padł, ale czy `defer` się wykonał?" → tak. To jest główny powód, dla którego `defer` istnieje.
3. **Argumenty `defer` liczone są od razu** — zaskakująca pułapka:
   ```go
   x := 1
   defer fmt.Println("wartość x:", x)
   x = 100
   // wypisze: wartość x: 1
   ```
   > "Wypisało 1, choć `x` na końcu było 100. Kiedy Go policzyło argument?"
   → w momencie napisania `defer`, nie w momencie wykonania.
   Jeśli chcesz aktualną wartość — użyj domknięcia z 5.2:
   ```go
   defer func() { fmt.Println("wartość x:", x) }()   // wypisze 100
   ```
4. **Zasięg blokowy:**
   ```go
   func zasieg() {
       a := 1
       if true {
           b := 2
           fmt.Println(a, b)     // OK — widać oba
       }
       // fmt.Println(b)         // BŁĄD: undefined: b
   }
   ```
   > "Zmienna żyje w klamrach, w których powstała. Gdzie jeszcze widziałeś tę zasadę?" → instrukcja inicjująca w `if` (3.1) i `switch` (3.2)
5. **Przesłanianie (shadowing)** — pułapka warta zapamiętania:
   ```go
   x := "zewnętrzny"
   if true {
       x := "wewnętrzny"       // := tworzy NOWĄ zmienną
       fmt.Println(x)          // wewnętrzny
   }
   fmt.Println(x)              // zewnętrzny — nietknięty!
   ```
   > "Zmień `:=` na `=` w środku. Co teraz?" → zmienia zewnętrzną
   > "Kompilator nie protestował. Czemu to niebezpieczne?"
   → bo wygląda, jakbyś zmieniał tę samą zmienną. To będzie **bardzo** ważne przy `err` w module 6.
   Narzędzie: `go vet` czasem to wychwyci; `gopls` w edytorze podświetla.

## Krok 4 — Pogłębienie (10-15 min)

**Zmienne na poziomie pakietu:**
```go
package main

import "fmt"

var wersja = "1.0"          // widoczna w całym pliku i pakiecie

func pokaz() { fmt.Println(wersja) }

func main() { pokaz() }
```
> "Czemu tu `var`, a nie `:=`?" → `:=` działa tylko wewnątrz funkcji (uczeń sprawdzał w 2.1)
**Rada:** zmiennych na poziomie pakietu używaj oszczędnie — każda funkcja może je zmienić, więc trudno prześledzić, kto zepsuł wartość. Stałe (`const`) są bezpieczne:
```go
const maksymalnaLiczbaProb = 3
```

**Podział na dwa pliki** — uczeń tworzy `kurs/zadania/15-defer/pomocnicze.go`:
```go
package main

func Podwoj(x int) int { return x * 2 }
func potroj(x int) int { return x * 3 }
```
i w `main.go` używa obu:
```go
fmt.Println(Podwoj(5), potroj(5))
```
Uruchomienie bez zmian: `go run ./15-defer` — Go bierze **wszystkie** pliki katalogu.
> "Nie było żadnego `import`. Czemu?" → oba pliki są w tym samym pakiecie (`package main`). Pakiet to katalog, nie plik.

**Wielka litera = widoczność na zewnątrz:**
| Nazwa | Widoczna z innych pakietów |
| --- | --- |
| `Podwoj`, `Wersja`, `Klient` | tak (eksportowana) |
| `potroj`, `wersja`, `klient` | nie (prywatna dla pakietu) |

> "W innych językach służą do tego słowa `public` i `private`. Go używa wielkości pierwszej litery. Co o tym sądzisz?"
Uczeń zna już tę zasadę z `fmt.Println` — wielkie `P`, bo wołamy je spoza pakietu `fmt`.

**Pełny własny pakiet** (osobny katalog + `import`) to temat 10.2, przy modułach. Tu wystarczy podział na pliki.

- 🔥 Funkcja z trzema `defer` i dwoma `return` w różnych gałęziach `if` — przewidź kolejność **przed** uruchomieniem, potem sprawdź
- ⭐ Rozbij wcześniejszy program na dwa pliki: `main.go` (tylko `main`) i `logika.go` (reszta funkcji)
- ⚡ Napisz funkcję, w której przesłonięcie zmiennej daje zły wynik, potem napraw ją zmianą jednego znaku (`:=` → `=`)

Kod ucznia: `kurs/zadania/15-defer/`.

## Pułapki
- **Argumenty `defer` liczone są w momencie deklaracji** — najczęstsze zaskoczenie. Gdy potrzebna aktualna wartość, opakuj w `func(){...}()`.
- **`defer` w pętli** — odkłada wykonanie do **końca funkcji**, nie końca obiegu. Otwieranie tysiąca plików w pętli z `defer plik.Close()` trzyma wszystkie otwarte do końca. Ratunek: wydzielić ciało pętli do osobnej funkcji.
- **Zapomniane nawiasy** — `defer func(){...}` bez `()` na końcu nie wykona nic (`defer` wymaga **wywołania**). Kompilator to złapie: `expression in defer must be function call`.
- **Przesłanianie przez `:=`** — kompilator milczy, a zmiana trafia w kopię. Największa pułapka tej lekcji, wraca w module 6 z `err`.
- **Zmienne pakietowe zamiast parametrów** — kuszące, gdy funkcja potrzebuje wielu danych. Prowadzi do kodu, w którym nie wiadomo, kto co zmienił.
- **`defer` nie działa przy `os.Exit()`** — program kończy się natychmiast, sprzątanie się nie wykona. Rzadkie, ale warto wiedzieć.
