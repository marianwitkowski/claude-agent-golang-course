# Lekcja 7.2 — Metody i wskaźniki

## Cel
Po lekcji uczeń:
- Pisze metodę i rozumie, czym różni się od zwykłej funkcji
- Rozumie, czym jest wskaźnik, i używa `&` oraz `*`
- Wybiera świadomie między odbiornikiem wartościowym a wskaźnikowym
- Rozpoznaje panikę `nil pointer dereference` i wie, skąd się bierze

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Wysyłasz koledze przepis. Możesz wysłać kserokopię albo kartkę z napisem: 'przepis leży w mojej kuchni, w drugiej szufladzie'. Czym się różnią te dwie przesyłki?"

**Drugie pytanie:**
> "Kolega dopisuje do przepisu 'więcej cukru'. W którym wariancie zmieni się **twój** przepis?"

**Co chcesz usłyszeć:** przy kserokopii — nie; przy adresie do szuflady — tak, bo to ten sam kartka.

## Krok 2 — Mostek (10 min)
**Mostek:**
> "W lekcji 7.1 struktura była zawsze kserokopią. Dziś poznasz drugi sposób: przekazanie **adresu**. Nazywa się to wskaźnikiem."

Uczeń tworzy `kurs/zadania/20-metody/main.go`:

```go
package main

import "fmt"

func main() {
	x := 10
	p := &x            // p to ADRES x

	fmt.Println(x)     // 10
	fmt.Println(p)     // 0xc000012345 — adres w pamięci
	fmt.Println(*p)    // 10 — wartość spod adresu

	*p = 99            // zapis pod adres
	fmt.Println(x)     // 99 — zmieniło się x!
}
```

**Pytania:**
- "`&x` — co to daje?" → adres zmiennej `x`
- "`*p` — co to daje?" → to, co leży pod adresem
- "Ostatnia linia zmieniła `x`, choć nie napisaliśmy `x = `. Wróć do kartki z szufladą."

**Nazwij:** `&` = "weź adres", `*` = "sięgnij pod adres". Typ `*int` to "adres do liczby".

## Krok 3 — Eksperyment (20 min)

1. **Funkcja zmieniająca argument** — rozwiązanie problemu z 5.1:
   ```go
   func zwieksz(x *int) {
       *x = *x + 100
   }

   func main() {
       liczba := 5
       zwieksz(&liczba)
       fmt.Println(liczba)   // 105
   }
   ```
   > "Porównaj z wersją bez wskaźnika z lekcji 5.1. Co się zmieniło w wywołaniu?" → `&` przy argumencie
2. **Metoda — funkcja przypisana do typu:**
   ```go
   type Prostokat struct {
       Szerokosc, Wysokosc float64
   }

   func (p Prostokat) Pole() float64 {
       return p.Szerokosc * p.Wysokosc
   }

   func main() {
       r := Prostokat{Szerokosc: 3, Wysokosc: 4}
       fmt.Println(r.Pole())
   }
   ```
   > "`(p Prostokat)` przed nazwą — co to jest?" → **odbiornik** (receiver): mówi, do jakiego typu należy ta metoda
   > "Czym `r.Pole()` różni się od `Pole(r)`?" → zapisem i tym, że metoda "należy" do typu. Działanie jest to samo.
   > "Gdzie widziałeś już taki zapis?" → `czytnik.Text()` (2.4), `err.Error()` (6.1)
3. **Metoda, która chce coś zmienić:**
   ```go
   func (p Prostokat) Skaluj(k float64) {
       p.Szerokosc *= k          // kopia!
       p.Wysokosc *= k
   }

   func main() {
       r := Prostokat{Szerokosc: 3, Wysokosc: 4}
       r.Skaluj(2)
       fmt.Println(r)            // {3 4} — bez zmian
   }
   ```
   > "Czemu nie zadziałało?" → odbiornik wartościowy to kopia, dokładnie jak parametr funkcji
4. **Odbiornik wskaźnikowy** — naprawa:
   ```go
   func (p *Prostokat) Skaluj(k float64) {
       p.Szerokosc *= k
       p.Wysokosc *= k
   }

   func main() {
       r := Prostokat{Szerokosc: 3, Wysokosc: 4}
       r.Skaluj(2)
       fmt.Println(r)            // {6 8}
   }
   ```
   > "Zwróć uwagę: wywołanie wygląda **tak samo** (`r.Skaluj(2)`), choć metoda chce wskaźnika. Go samo dopisuje `&`."
   > "I odwrotnie: gdy masz wskaźnik `p` i wołasz `p.Pole()`, Go samo dopisuje `*`. Dlatego wskaźniki w Go są mniej uciążliwe, niż się wydaje."
5. **`nil` pointer** — panika, którą uczeń musi rozpoznać:
   ```go
   var p *Prostokat
   fmt.Println(p)        // <nil>
   // fmt.Println(p.Pole())   // panic: runtime error: invalid memory address or nil pointer dereference
   ```
   > "Wskaźnik, który na nic nie wskazuje. Kiedy taki powstaje?" → gdy zadeklarujesz go bez przypisania albo gdy funkcja zwróci `nil` przy błędzie
   **Stąd zasada z 6.1: najpierw sprawdź `err`, dopiero potem używaj wyniku.**
6. **Wskaźnik do struktury — tworzenie:**
   ```go
   r := &Prostokat{Szerokosc: 3, Wysokosc: 4}   // od razu wskaźnik
   fmt.Println(r.Pole())                         // działa, bez gwiazdki
   fmt.Printf("%+v\n", *r)                       // pełna zawartość
   ```
   > "Zauważ: `r.Pole()`, a nie `(*r).Pole()`. Go robi to za ciebie."

## Krok 4 — Pogłębienie (10 min)

**Kiedy który odbiornik — reguła praktyczna:**
| Sytuacja | Odbiornik |
| --- | --- |
| Metoda zmienia strukturę | `*T` (wskaźnikowy) |
| Struktura jest duża (kopiowanie kosztuje) | `*T` |
| Struktura jest mała i metoda tylko czyta | `T` |
| **Choć jedna metoda typu ma `*T`** | wszystkie dawaj `*T` |

Ostatni wiersz to konwencja Go: **spójność w obrębie typu**. Mieszanie myli i powoduje subtelne błędy przy interfejsach (moduł 8).

**Konstruktor zwracający wskaźnik:**
```go
func NowyProstokat(sz, w float64) (*Prostokat, error) {
	if sz <= 0 || w <= 0 {
		return nil, errors.New("wymiary muszą być dodatnie")
	}
	return &Prostokat{Szerokosc: sz, Wysokosc: w}, nil
}
```
> "Czemu przy błędzie zwracamy `nil`, a nie pustą strukturę?" → bo `nil` jest jednoznaczny: nie ma obiektu. Wywołujący **musi** sprawdzić `err`.

**Metody na własnych typach nie tylko strukturalnych:**
```go
type Celsjusz float64

func (c Celsjusz) NaFahrenheita() float64 {
	return float64(c)*9/5 + 32
}

fmt.Println(Celsjusz(100).NaFahrenheita())   // 212
```
> "Metodę można dodać do **każdego własnego typu**, nie tylko do struktury. Nie można tylko do typów z innych pakietów."

**Czego w Go nie ma:**
- arytmetyki wskaźników (`p+1` jak w C) — celowo, to źródło błędów pamięci
- ręcznego zwalniania pamięci — zajmuje się tym odśmiecacz (garbage collector)
> "Wskaźnik w Go jest bezpieczny: albo wskazuje na coś prawdziwego, albo jest `nil`. Nie da się wskazać w przypadkowe miejsce pamięci."

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "metody i wskaźniki". Sugerowane:
- 🔥 Struktura `Kolo` z polem `Promien`, metody `Pole()` i `Obwod()` (odbiornik wartościowy)
- ⭐ Struktura `Licznik` z metodami `Zwieksz()`, `Zeruj()` i `Wartosc()` — pierwsze dwie muszą działać, więc dobierz odbiorniki
- ⚡ Struktura `Konto` z `Wplac(kwota)` i `Wyplac(kwota) error`; `Wyplac` zwraca błąd przy braku środków; napisz też `NoweKonto` zwracające `(*Konto, error)`

## Pułapki
- **Odbiornik wartościowy przy metodzie, która ma zmieniać** — metoda "działa", ale nic nie zmienia. Najczęstszy błąd tej lekcji, kompilator milczy.
- **`nil pointer dereference`** — druga najczęstsza panika w Go (po `index out of range`). Zwykle: użycie wyniku funkcji bez sprawdzenia `err`.
- **Mieszanie odbiorników w jednym typie** — działa, ale prowadzi do problemów przy interfejsach (moduł 8). Trzymaj jeden styl.
- **Metoda z odbiornikiem `*T` na wartości niemodyfikowalnej** — `Prostokat{1,2}.Skaluj(2)` się nie skompiluje (`cannot take address`). Potrzebna zmienna.
- **`*` w dwóch znaczeniach** — w typie (`*int` to "wskaźnik do int") i w wyrażeniu (`*p` to "wartość spod p"). Mylące na początku; warto nazwać wprost.
- **Wskaźnik do elementu slice'a** — po `append` może wskazywać na stary magazyn (pułapka z 4.2). Rzadkie u początkującego, ale realne.

## Notatki tutora
- **To najtrudniejsza lekcja w kursie dla osoby, która nigdy nie programowała.** Zaplanuj więcej czasu, rozważ podział na dwie sesje: (a) wskaźniki na `int`, (b) metody i odbiorniki.
- **Nie tłumacz pamięci, stosu ani sterty.** Analogia "adres do szuflady" wystarczy do końca kursu.
- **Eksperymenty 3 → 4 to serce lekcji:** ta sama metoda, jedna gwiazdka różnicy, zupełnie inne zachowanie. Uczeń musi to zobaczyć na własne oczy, nie usłyszeć.
- Jeśli uczeń pyta "to kiedy w końcu używać wskaźników" — daj prostą regułę na start: **struktury zmieniane → wskaźnik; wszystko inne → wartość.** Subtelności przyjdą z praktyką.
- Jeśli uczeń zna klasy z innego języka: "metoda z odbiornikiem to mniej więcej to samo, co metoda w klasie — tylko zapisane osobno od danych".
