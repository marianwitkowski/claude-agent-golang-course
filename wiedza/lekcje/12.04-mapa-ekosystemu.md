## Krok 3 — Mapa terenu (20 min)

**A. Aplikacja webowa** — najczęstszy kierunek w Go
```go
package main

import (
	"fmt"
	"net/http"
)

func main() {
	http.HandleFunc("GET /witaj/{imie}", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "Cześć, %s!", r.PathValue("imie"))
	})
	http.ListenAndServe(":8080", nil)
}
```
> "Pięć linii i masz serwer. Zauważ `w http.ResponseWriter` — to `io.Writer` z lekcji 8.2. Cała twoja wiedza działa dalej."
- w bibliotece standardowej: `net/http` (od 1.22 z routingiem wzorcowym — wcześniej wymagało biblioteki)
- popularne biblioteki: **Gin**, **Fiber**, **Echo** (szybszy start, więcej gotowych rzeczy)
- co trzeba doczytać: HTTP (metody, kody stanu), REST, kontekst (`context.Context`)
- **kolejny krok:** przerób swój projekt CLI na serwer z tą samą logiką

**B. Bazy danych**
```go
db, err := sql.Open("postgres", polaczenie)
rows, err := db.Query("SELECT id, tresc FROM zadania WHERE zrobione = $1", false)
```
- w bibliotece standardowej: `database/sql` (interfejs, sterownik osobno)
- sterowniki: `pgx` (PostgreSQL), `go-sqlite3`, `go-sql-driver/mysql`
- warstwy wyżej: **sqlc** (generuje kod z SQL), **GORM** (mapowanie obiektowe)
- **wymaga:** znajomości SQL. To osobny temat, wart nauki niezależnie od Go.
- **najprostszy start:** SQLite — plik zamiast serwera

**C. Współbieżność na poważnie**
- `context.Context` — anulowanie i limity czasu, przekazywane przez cały łańcuch wywołań
- wzorce: pula robotników, rozgałęzianie i scalanie, potoki
- `sync/atomic`, `errgroup` z `golang.org/x/sync`
- **wymaga:** solidnego opanowania modułu 11 i nawyku `-race`

**D. Narzędzia wiersza poleceń — poziom wyżej**
- **cobra** — podkomendy, autouzupełnianie, pomoc (używa go `kubectl`, `gh`, `docker`)
- **bubbletea** — interfejsy tekstowe z widokami i klawiszami
- **goreleaser** — automatyczne wydania na wszystkie systemy
- **najbliżej tego, co już umiesz** — dobry kolejny krok, jeśli podobał ci się projekt

**E. Generyki** — jedyny duży element języka pominięty w kursie
```go
func Mapuj[T, U any](s []T, f func(T) U) []U {
	wynik := make([]U, 0, len(s))
	for _, v := range s {
		wynik = append(wynik, f(v))
	}
	return wynik
}
```
> "Funkcja działająca na dowolnym typie, z zachowaniem kontroli typów. Nie potrzebowałeś ich do tej pory — i to normalne. Przydają się przy pisaniu bibliotek."

**F. Mikroserwisy, chmura, konteneryzacja**
- Docker (obraz z binarką Go bywa mniejszy niż 20 MB), Kubernetes (napisany w Go)
- gRPC, kolejki komunikatów, obserwowalność
- **to poziom architektury, nie języka.** Sensowne po roku praktyki, nie teraz.

**G. Gdzie szukać wiedzy:**

## Krok 4 — Plan na dalej (10 min)

**Uczeń wybiera JEDNĄ rzecz** i zapisuje w `kurs/lekcje/12.04-plan.md`:

```markdown
## Mój następny krok
Kierunek: [web / bazy danych / CLI / współbieżność]
Projekt: ____________________
Pierwszy konkretny krok: ____________________
Termin pierwszego kroku: ____________________
```

**Pytania pomocnicze:**
- "Co chcesz zbudować w najbliższym miesiącu? Konkretnie, nie 'coś webowego'."
- "Jaki jest **pierwszy** krok, który zajmie mniej niż dwie godziny?"
- "Kiedy dokładnie usiądziesz do tego pierwszy raz?"

**Rady na dalszą naukę:**
1. **Pisz kod, nie czytaj o kodzie.** Godzina pisania uczy więcej niż pięć godzin tutoriali.
2. **Czytaj cudzy kod.** Biblioteka standardowa Go jest napisana czytelnie — `go doc -src fmt.Println` pokaże źródło.
3. **Kończ projekty.** Trzy skończone małe programy uczą więcej niż dziesięć zaczętych dużych.
4. **Wracaj do własnego kodu po miesiącu.** Zobaczysz, ile się nauczyłeś.
5. **Nie przesiadaj się na kolejny język zbyt szybko.** Głębia w jednym bije powierzchowność w pięciu.

- **Uczenie się pięciu rzeczy naraz** — kończy się umiejętnością żadnej.
- **Kolejny kurs zamiast własnego projektu** — bierność w przebraniu nauki.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
Co się zmieniło od materiałów źródłowych i warto o tym wiedzieć, wchodząc dalej:
- `net/http` ma **routing wzorcowy** od 1.22 (`GET /rzeczy/{id}`) — do wielu zastosowań framework nie jest już potrzebny
- `log/slog` (1.21) to standard logowania w nowych projektach
- `encoding/json` na silniku v2 (1.27) — szybszy i surowszy
- pakiet `uuid` w bibliotece standardowej (1.27)
- `testing/synctest` (1.25) — testowanie kodu współbieżnego bez czekania
- generyki (1.18) są już powszechne w bibliotekach; warto je rozumieć jako czytelnik, zanim zaczniesz pisać własne
