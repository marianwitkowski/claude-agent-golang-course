# Lekcja 4.1 — Tablice i slice'y

## Cel
Po lekcji uczeń:
- Tworzy slice i sięga po element przez indeks
- Rozumie różnicę: tablica ma **stały** rozmiar, slice rośnie
- Wie, dlaczego indeksy zaczynają się od zera i gdzie kończą
- Rozpoznaje `index out of range` i wie, co go powoduje

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Chcesz zapisać oceny z pięciu sprawdzianów. Jak to zrobisz na kartce? A jak w programie, gdybyś miał tylko to, co znasz do tej pory?"

**Co chcesz usłyszeć:** pięć osobnych zmiennych — `ocena1`, `ocena2`, ... To działa.

**Drugie pytanie — tu ma zaboleć:**
> "A teraz szkoła kupiła nowy dziennik i sprawdzianów jest trzydzieści. Ile zmiennych napiszesz? A jak policzysz ich średnią?"

→ trzydzieści zmiennych i trzydziestoelementowe dodawanie. Nie do utrzymania.

## Krok 2 — Mostek (10 min)
**Mostek:**
> "Potrzebujesz jednej nazwy na **całą listę** i sposobu, żeby wskazać element numerem. W Go nazywa się to **slice**."

Uczeń tworzy `kurs/zadania/09-slices/main.go`:

```go
package main

import "fmt"

func main() {
	oceny := []int{4, 5, 3, 5, 2}

	fmt.Println(oceny)
	fmt.Println(oceny[0])
	fmt.Println(len(oceny))
}
```

**Pytania:**
- "`[]int` — co znaczy każdy z tych fragmentów?" → `[]` lista, `int` czego
- "`oceny[0]` dało 4, czyli pierwszy element. Co da `oceny[1]`?"
- "Skoro pierwszy ma numer 0, to jaki numer ma ostatni z pięciu?" → 4, nie 5
- "`len(oceny)` dało 5. Jaki jest **największy dozwolony indeks**?" → `len - 1`

Nazwij: **slice**, **element**, **indeks**, **długość**.

## Krok 3 — Eksperyment (15-20 min)

1. Uczeń wypisuje po kolei `oceny[0]` do `oceny[4]`, potem próbuje `oceny[5]`.
   → program się kompiluje, ale przy uruchomieniu:
   `panic: runtime error: index out of range [5] with length 5`
   > "Wklej cały komunikat. Które dwie liczby ci mówią, na czym polega problem?"
   > "Czy kompilator to złapał?" → nie, dopiero uruchomienie. Jak dzielenie przez zero z 2.2.
2. **Zmiana elementu:**
   ```go
   oceny[4] = 5
   fmt.Println(oceny)
   ```
3. **Pętla po elementach** — połączenie z 3.3:
   ```go
   for i := 0; i < len(oceny); i++ {
       fmt.Printf("sprawdzian %d: ocena %d\n", i+1, oceny[i])
   }
   ```
   > "Czemu w nagłówku jest `i < len(oceny)`, a nie `i <= len(oceny)`?"
   > "Czemu przy wypisywaniu jest `i+1`?" → bo człowiek liczy sprawdziany od 1, komputer indeksy od 0
4. **Suma i średnia** — uczeń pisze sam (to odpowiedź na ból z kroku 1):
   ```go
   suma := 0
   for i := 0; i < len(oceny); i++ {
       suma += oceny[i]
   }
   srednia := float64(suma) / float64(len(oceny))
   fmt.Printf("Średnia: %.2f\n", srednia)
   ```
   > "Czemu obie konwersje na `float64`? Co dostaniesz bez nich?" → dzielenie całkowite z 2.2
5. **Pusty slice i wartość zerowa:**
   ```go
   var pusty []int
   fmt.Println(pusty, len(pusty), pusty == nil)
   ```
   → `[] 0 true`
   > "Wartością zerową slice'a jest `nil` — 'jeszcze nic tu nie ma'. Ale `len` na nim działa i daje 0, więc pętla po nim po prostu nie wykona ani jednego obiegu. Wygodne."
6. **Slice tekstów i wartości logicznych:**
   ```go
   imiona := []string{"Anna", "Piotr", "Ewa"}
   flagi := []bool{true, false}
   ```
   > "Czy w jednym slice mogą być i liczby, i teksty?" → nie. Slice ma **jeden** typ elementu. Niech spróbuje `[]int{1, "dwa"}`.

## Krok 4 — Pogłębienie (10-15 min)

**Tablica vs slice** — uczeń pisze obie:
```go
var tab [3]int          // TABLICA: rozmiar 3 jest częścią typu
sl := []int{1, 2, 3}    // SLICE: bez liczby w nawiasach

fmt.Println(tab, sl)
```
**Pytania:**
- "Jaka jest różnica w zapisie?" → liczba w nawiasach kwadratowych
- "Spróbuj dodać czwarty element do `tab`." → nie da się, rozmiar jest częścią typu
- "`[3]int` i `[4]int` to ten sam typ?" → **nie**, to dwa różne typy. Funkcja przyjmująca `[3]int` nie przyjmie `[4]int`.

> "Dlatego w praktyce w Go **prawie zawsze używa się slice'ów**. Tablice zobaczysz rzadko. Zapamiętaj, że istnieją, używaj slice'ów."

**Wycinek slice'a** (stąd nazwa):
```go
liczby := []int{10, 20, 30, 40, 50}

fmt.Println(liczby[1:3])   // [20 30] — od 1 włącznie, do 3 WYŁĄCZNIE
fmt.Println(liczby[:2])    // [10 20] — od początku
fmt.Println(liczby[3:])    // [40 50] — do końca
fmt.Println(liczby[:])     // cały
```
> "Ile elementów ma `liczby[1:3]`? Jak to policzyć bez patrzenia na wynik?" → `3-1 = 2`. Górna granica jest **wyłączna** — dokładnie jak `i < len` w pętli. To ta sama konwencja.

**Typowy błąd początkującego:**
```go
// fmt.Println(liczby[1:10])   // panic: slice bounds out of range
```

**Slice tekstu** — działa, ale ostrożnie:
```go
s := "Gołąb"
fmt.Println(s[0:2])   // "Go"
fmt.Println(len(s))   // 7, nie 5! — "ł" i "ą" zajmują po 2 bajty
```
> "Pięć liter, a `len` mówi siedem. Tekst w Go liczy się w **bajtach**, nie w literach — `G`, `o` i `b` po jednym bajcie, `ł` i `ą` po dwa. Na razie zapamiętaj: nie tnij tekstu z ogonkami po indeksach."

**Zanim uczeń uruchomi — zapytaj o przewidywanie:** "Ile twoim zdaniem wypisze `len`?" Prawie każdy powie 5. Rozbieżność między 5 a 7 jest tu całą lekcją; nie psuj jej, podając liczbę wcześniej.
(Pełne wyjaśnienie — `rune`, UTF-8 — poza kursem; wystarczy ostrzeżenie.)

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "slice'y". Sugerowane:
- 🔥 Slice 5 imion, wypisz każde w osobnej linii z numerem porządkowym (od 1!)
- ⭐ Slice liczb: znajdź największą i najmniejszą, wypisz obie (bez `slices.Max` — pętlą)
- ⚡ Slice temperatur z tygodnia: policz średnią i wypisz, które dni były powyżej średniej (dwie pętle po tym samym slice)

Kod ucznia: `kurs/zadania/09-slices/`.

## Pułapki
- **`index out of range`** — kompilator nie łapie, program pada przy uruchomieniu. Zawsze pętla do `i < len(x)`.
- **Ostatni element to `x[len(x)-1]`**, nie `x[len(x)]`.
- **Mylenie `len` z ostatnim indeksem** — najczęstsze źródło paniki. Powtarzaj.
- **Górna granica wycinka jest wyłączna** — `x[0:3]` to trzy elementy: 0, 1, 2.
- **Tablica `[3]int` ≠ slice `[]int`** — jeśli uczeń przypadkiem napisze `[3]int` i potem nie może dodać elementu, to jest przyczyna.
- **`len(tekst)` liczy bajty** — dla tekstu bez polskich znaków wynik jest zgodny z intuicją, z ogonkami nie.
- **Porównywanie slice'ów przez `==`** → błąd kompilacji (`slice can only be compared to nil`). Do porównania: `slices.Equal(a, b)`.

## Aktualizacja 2026 (z `AKTUALIZACJE.md`)
Pakiet **`slices`** jest w bibliotece standardowej od 1.21 — pokaż na **końcu** lekcji, po tym jak uczeń napisał pętle sam:
```go
import "slices"

fmt.Println(slices.Max(oceny))
fmt.Println(slices.Contains(imiona, "Anna"))
slices.Sort(oceny)
```
> "Napisałeś to pętlą i wiesz, jak działa. Teraz możesz pisać krócej — ale najpierw musiałeś zrozumieć."

Materiały sprzed 2021 używają `sort.Ints(s)` — dziś to `slices.Sort(s)`.

## Notatki tutora
- **Liczenie od zera jest tu głównym progiem.** Jeśli uczeń się myli — nie tłumacz teoretycznie, każ mu wypisać `i` i `oceny[i]` obok siebie w pętli. Zobaczy sam.
- **Nie wprowadzaj `append`** — to następna lekcja. Jeśli uczeń pyta "a jak dodać element" → "brawo, dokładnie o tym jest 4.2".
- **Nie wprowadzaj `range`** — to 4.4. Klasyczna pętla z indeksem jest tu celowa: uczeń ma zobaczyć indeksy na oczy, zanim `range` je schowa.
- Nie wchodź w wewnętrzną budowę slice'a (wskaźnik, długość, pojemność). Pojemność wchodzi w 4.2, reszta nigdy.
- Jeśli uczeń narzeka, że "to skomplikowane" — wróć do kroku 1: trzydzieści zmiennych. Slice jest **prostszy** niż to, co zastępuje.
