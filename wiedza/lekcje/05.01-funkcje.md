# Lekcja 5.1 — Funkcje

## Cel
Po lekcji uczeń:
- Pisze własną funkcję z parametrami i wartością zwracaną
- Zwraca dwie wartości i rozumie, dlaczego w Go to codzienność
- Rozumie, że argumenty są przekazywane przez **kopię**
- Wie, kiedy wydzielić kod do funkcji

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Robisz kawę dla pięciu osób. Za każdym razem: nasyp, zalej, zamieszaj. Czy opisujesz sobie te trzy kroki w głowie pięć razy, czy masz jedno pojęcie 'zrób kawę'?"

**Drugie pytanie:**
> "'Zrób kawę' — ale z cukrem czy bez? To samo pojęcie, ale coś się zmienia. Jak byś to nazwał?"

→ szczegół podawany przy każdym użyciu. To parametr.

**Trzecie:**
> "I na końcu dostajesz kubek. Czyli coś oddajesz temu, kto prosił."

## Krok 2 — Mostek (10 min)
**Mostek:**
> "Nazwana czynność, która przyjmuje szczegóły i coś oddaje, to **funkcja**. Piszesz raz, używasz ile chcesz. `main` też jest funkcją — tylko tą, od której Go zaczyna."

Uczeń tworzy `kurs/zadania/13-funkcje/main.go`:

```go
package main

import "fmt"

func pole(szerokosc int, wysokosc int) int {
	return szerokosc * wysokosc
}

func main() {
	fmt.Println(pole(3, 4))
	fmt.Println(pole(10, 2))
}
```

**Pytania — rozbierz nagłówek:**
- "`func pole` — co to?" → słowo kluczowe i nazwa
- "`(szerokosc int, wysokosc int)` — co to?" → parametry: nazwa i typ każdego
- "`int` przed klamrą — co oznacza?" → typ tego, co funkcja odda
- "Co robi `return`?" → oddaje wartość i **kończy** funkcję
- "Ile razy napisałeś mnożenie? Ile razy go użyłeś?"

**Skrót przy tych samych typach:** `func pole(szerokosc, wysokosc int) int` — uczeń zmienia i sprawdza, że działa.

## Krok 3 — Eksperyment (15-20 min)

1. **Funkcja bez zwracania:**
   ```go
   func przywitaj(imie string) {
       fmt.Printf("Cześć, %s!\n", imie)
   }
   ```
   > "Nie ma typu po nawiasach ani `return`. Kiedy taka funkcja ma sens?" → gdy robi coś (wypisuje, zapisuje), a nie liczy
2. **`return` kończy natychmiast:**
   ```go
   func sprawdz(wiek int) string {
       if wiek < 0 {
           return "błędny wiek"
       }
       if wiek < 18 {
           return "niepełnoletni"
       }
       return "pełnoletni"
   }
   ```
   > "Ile razy wykona się `return` przy jednym wywołaniu?" → dokładnie raz. Pierwszy napotkany kończy funkcję.
   > "Usuń ostatni `return` i skompiluj." → `missing return`. Kompilator pilnuje, żeby każda ścieżka coś zwracała.
3. **Dwie wartości zwracane** — cecha, którą uczeń już widział w `strconv.Atoi`:
   ```go
   func podziel(a, b int) (int, bool) {
       if b == 0 {
           return 0, false
       }
       return a / b, true
   }

   func main() {
       wynik, ok := podziel(10, 2)
       fmt.Println(wynik, ok)

       wynik2, ok2 := podziel(10, 0)
       fmt.Println(wynik2, ok2)
   }
   ```
   > "Przypomina ci to coś z lekcji 2.4 i 4.3?" → `strconv.Atoi` i `wartosc, ok := mapa[klucz]`
   > "Czemu przy dzieleniu przez zero zwracamy `0, false`, a nie samo `false`?" → bo funkcja **musi** zwrócić tyle wartości, ile deklaruje
4. **Ignorowanie części wyniku:**
   ```go
   wynik, _ := podziel(10, 2)
   ```
   > "Znasz `_` z `range`. Tu robi to samo."
5. **Argumenty to kopie** — ważny eksperyment:
   ```go
   func zwieksz(x int) {
       x = x + 100
       fmt.Println("w funkcji:", x)
   }

   func main() {
       liczba := 5
       zwieksz(liczba)
       fmt.Println("po wyjściu:", liczba)   // 5 — bez zmian!
   }
   ```
   > "Funkcja dostała **kopię**. Pamiętasz `range` z 4.4? To ta sama zasada."
   > "A jak zmienić oryginał?" → wskaźniki (7.2) albo — prościej — zwrócić nową wartość i przypisać
6. **A slice? Sprawdź sam:**
   ```go
   func zepsuj(s []int) {
       s[0] = 999
   }

   func main() {
       liczby := []int{1, 2, 3}
       zepsuj(liczby)
       fmt.Println(liczby)   // [999 2 3] ← zmieniło się!
   }
   ```
   > "Dlaczego tu zadziałało, a przy `int` nie? Wróć do lekcji 4.2."
   → skopiowany został **uchwyt** do magazynu, ale magazyn jest ten sam. Mapy zachowują się tak samo.

## Krok 4 — Pogłębienie (10 min)

**Nazwane wartości zwracane** — uczeń zobaczy to w cudzym kodzie:
```go
func podziel2(a, b int) (wynik int, ok bool) {
	if b == 0 {
		return          // "nagi return" — zwraca wynik=0, ok=false
	}
	wynik = a / b
	ok = true
	return
}
```
> "Co robi samo `return` bez wartości?" → zwraca aktualne wartości nazwanych zmiennych
**Rada:** nazwy w deklaracji są dobre jako dokumentacja, ale "nagiego `return`" unikaj w dłuższych funkcjach — trudno prześledzić, co właściwie wyszło.

**Kiedy wydzielić funkcję?** Praktyczne kryteria dla ucznia:
- ten sam fragment pojawia się drugi raz
- da się mu nadać sensowną nazwę ("policzŚrednią", "sprawdźPoprawność")
- `main` przestaje się mieścić na ekranie

**Nazewnictwo:**
- `camelCase`: `policzSume`, nie `policz_sume`
- czasownik na początku, bo funkcja coś robi
- **wielka pierwsza litera ma znaczenie** — `Pole` jest widoczne z innych pakietów, `pole` nie. Szczegóły w 5.3.

**Kolejność funkcji w pliku nie ma znaczenia** — uczeń może wywołać funkcję zdefiniowaną niżej. Konwencja: `main` na górze, pomocnicze pod nią.

**Funkcja w funkcji:**
```go
func main() {
	kwadrat := func(x int) int { return x * x }
	fmt.Println(kwadrat(5))
}
```
> "Funkcja bez nazwy, przypisana do zmiennej. Wrócimy do tego w 5.2."

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "funkcje". Sugerowane:
- 🔥 Funkcja `poleKola(promien float64) float64`, wywołana dla trzech różnych promieni
- ⭐ Funkcja `srednia(oceny []int) float64` — użyj slice'a i pętli z modułu 4; obsłuż pustą listę (zwróć drugą wartość `ok`)
- ⚡ Rozbij dowolny wcześniejszy program (np. FizzBuzz albo kalkulator) na funkcje tak, żeby `main` miał maksymalnie 10 linii

## Pułapki
- **`missing return`** — każda ścieżka musi kończyć się `return`. Kompilator jest tu surowy i nie akceptuje "przecież tu zawsze wejdzie".
- **Liczba i typy zwracanych wartości muszą się zgadzać dokładnie** — `not enough return values`.
- **Nieużyty wynik funkcji** — Go **pozwala** zignorować wynik zwykłej funkcji (inaczej niż nieużywaną zmienną). `podziel(10, 2)` bez przypisania skompiluje się bez słowa. To realne źródło błędów, zwłaszcza gdy funkcja zwraca błąd (moduł 6).
- **Zmiana parametru nie zmienia oryginału** — dla `int`, `string`, `bool`, `float64` i struktur (moduł 7).
- **...ale dla slice i mapy zmiana zawartości działa na oryginale.** Dwie różne zasady, które trzeba rozróżnić.
- **Nazwana wartość zwracana + `:=` w środku** — `wynik := 5` tworzy **nową** zmienną zasłaniającą tę z nagłówka. Klasyczny, trudny do zauważenia błąd.

## Notatki tutora
- **Nie wprowadzaj `error`** jako typu — to moduł 6. Tutaj druga wartość to `bool` (`ok`). Uczeń dostanie prawdziwy `error` za jedną lekcję i zobaczy, że to ten sam wzorzec.
- **Eksperymenty 5 i 6 razem** (kopia `int` vs współdzielony slice) to sedno. Nie rozdzielaj ich.
- Jeśli uczeń pyta "czemu Go nie ma wyjątków" — powiedz: "moduł 6, cały jest o tym". Nie uprzedzaj.
- Jeśli uczeń pyta o argumenty domyślne albo nazwane (`pole(szerokosc: 3)`) — **Go tego nie ma**. Świadoma decyzja: jedna funkcja, jedno zachowanie. Zamiennik: osobna funkcja albo struktura z opcjami (moduł 7).
- Wydzielanie funkcji to nawyk, nie wiedza. Warto **przy każdym kolejnym ćwiczeniu** pytać: "da się to podzielić na dwie nazwane części?"
