# Lekcja 3.1 — `if` / `else if` / `else`

## Cel
Po lekcji uczeń:
- Pisze warunek, który wykonuje kod tylko wtedy, gdy coś jest prawdą
- Buduje łańcuch `if` / `else if` / `else` i rozumie, że kończy się na pierwszym pasującym
- Używa instrukcji inicjującej: `if x := ...; warunek`
- Rozumie, dlaczego w Go nie ma nawiasów wokół warunku, a klamry są obowiązkowe

## Krok 1 — Zakotwiczenie (5 min)
**Pytanie wejściowe:**
> "Wychodzisz z domu. Jak decydujesz, czy brać parasol? Powiedz to na głos, tak jak myślisz."

**Co chcesz usłyszeć:** "jeśli pada / jeśli zapowiadają deszcz, to biorę; w przeciwnym razie nie".

**Drugie pytanie:**
> "A teraz trudniej: kurtka. Jeśli poniżej zera — zimowa, jeśli poniżej 15 stopni — jesienna, w przeciwnym razie żadna. Powiedz to w tej samej kolejności co przed chwilą. Czy kolejność sprawdzania ma znaczenie?"

→ ma. Gdyby najpierw sprawdzić "poniżej 15", przy -5 stopniach wyszłaby jesienna.

## Krok 2 — Mostek (10 min)
**Mostek:**
> "To co powiedziałeś to gotowy kod. Go zapisuje to prawie dosłownie."

Uczeń tworzy `kurs/zadania/06-warunki/main.go`:

```go
package main

import "fmt"

func main() {
	temperatura := 10

	if temperatura < 0 {
		fmt.Println("Kurtka zimowa")
	} else if temperatura < 15 {
		fmt.Println("Kurtka jesienna")
	} else {
		fmt.Println("Bez kurtki")
	}
}
```

**Pytania:**
- "Czego brakuje wokół warunku w porównaniu do tego, co widziałeś w innych językach albo w matematyce?" → nawiasów. W Go `if (x < 0)` się skompiluje, ale `gofmt` je usunie — nie są potrzebne.
- "Zmień `temperatura` na `-5`. Który blok się wykona? A ile bloków w sumie?" → **dokładnie jeden**, pierwszy pasujący
- "Zmień na `20`. Co teraz?"

Nazwij: **warunek**, **blok**, **gałąź**.

## Krok 3 — Eksperyment (15 min)

1. Uczeń ustawia `temperatura := 10` i **zamienia kolejność** dwóch pierwszych warunków (`< 15` przed `< 0`). Sprawdza dla `-5`.
   > "Co się zepsuło? Wróć do pierwszego pytania z tej lekcji."
2. **Klamry są obowiązkowe** — uczeń próbuje skrótu z innych języków:
   ```go
   // if temperatura < 0
   //     fmt.Println("zimno")
   ```
   → `syntax error: unexpected fmt, expected {`
   > "Go nie pozwala pominąć klamer nawet przy jednej linii. Zysk czy strata?"
   → zysk: nie da się popełnić błędu polegającego na dopisaniu drugiej linii, która wygląda jakby była w środku, a nie jest.
3. **`else` musi być w tej samej linii co `}`** — uczeń próbuje:
   ```go
   }
   else {
   ```
   → `syntax error: unexpected else, expected }`
   > "To ta sama zasada co z klamrą przy `func main()` z lekcji 1.2 — pamiętasz o średnikach wstawianych na końcu linii?"
4. **Warunki złożone** — uczeń pisze:
   ```go
   wiek := 20
   maBilet := true

   if wiek >= 18 && maBilet {
       fmt.Println("Wpuszczamy")
   } else {
       fmt.Println("Nie wpuszczamy")
   }
   ```
   > "Zmień jedną wartość tak, żeby zmienić wynik. Które zmiany działają, a które nie?"
5. **Instrukcja inicjująca — idiom Go:**
   ```go
   if reszta := 17 % 5; reszta == 0 {
       fmt.Println("dzieli się równo")
   } else {
       fmt.Println("zostaje:", reszta)
   }
   // fmt.Println(reszta)   // BŁĄD: undefined: reszta
   ```
   > "Zmienna `reszta` istnieje tylko w środku `if` i `else`. Odkomentuj ostatnią linię i zobacz. Po co komu taka zmienna o krótkim życiu?"
   → żeby nie zaśmiecać reszty funkcji nazwami użytymi raz. To bardzo częsty zapis w Go.
6. **Połączenie z lekcją 2.4** — uczeń pisze program, który pyta o wiek i odpowiada:
   ```go
   wiek, err := strconv.Atoi(strings.TrimSpace(czytnik.Text()))
   if err != nil {
       fmt.Println("To nie jest liczba.")
       return
   }
   if wiek >= 18 {
       fmt.Println("Pełnoletni")
   } else {
       fmt.Println("Niepełnoletni")
   }
   ```
   > "Teraz rozumiesz już cały ten wzorzec z poprzedniej lekcji, prawda?"

## Krok 4 — Pogłębienie (10 min)

**Wzorzec "wczesnego wyjścia"** — pokaż dwa zapisy tego samego:
```go
// zagnieżdżony — im dalej, tym głębiej
if err == nil {
	if wiek >= 18 {
		fmt.Println("OK")
	}
}

// płaski — Go preferuje ten
if err != nil {
	return
}
if wiek < 18 {
	return
}
fmt.Println("OK")
```
> "Który łatwiej przeczytać, gdy warunków jest pięć?"
To fundament stylu Go: **obsłuż błędne przypadki od razu i wyjdź, główna droga zostaje po lewej stronie ekranu.** Wróci w module 6.

**Czego w Go nie ma:**
- operatora trójargumentowego `warunek ? a : b` — jest zwykły `if`. Autorzy uznali, że skrót zachęca do nieczytelnych zagnieżdżeń
- `if` jako wyrażenia (nie da się `x := if ...`)

**Warunek musi być typu `bool`** — inaczej niż w wielu językach:
```go
licznik := 0
// if licznik { }        // BŁĄD: non-boolean condition in if statement
if licznik != 0 { }      // OK
```
> "W innych językach zero znaczy fałsz, a niepusty tekst prawdę. Go tego nie robi. Zysk?"
→ nie ma zgadywania, co autor miał na myśli.

**Porównywanie tekstów** działa wprost:
```go
if imie == "Anna" { }
if strings.ToLower(imie) == "anna" { }   // bez znaczenia wielkości liter
```

## Krok 5 — Ćwiczenie
→ Skill `cwiczenie`. Temat: "warunki". Sugerowane:
- 🔥 Program pyta o liczbę i mówi, czy jest dodatnia, ujemna, czy zero
- ⭐ Oceny: liczba punktów 0-100 → ocena (>=90 bdb, >=75 db, >=50 dst, reszta ndst)
- ⚡ Rok przestępny: podzielny przez 4, ale nie przez 100, chyba że przez 400. Najpierw powiedz regułę słowami, dopiero potem pisz.

Kod ucznia: `kurs/zadania/06-warunki/`.

## Pułapki
- **`else` w nowej linii** → błąd składni. Zawsze `} else {`.
- **Zbędne nawiasy** `if (x > 0)` — kompiluje się, ale `gofmt` je usuwa. Nie walcz z formaterem.
- **`=` zamiast `==`** — w Go to błąd składni (`cannot use assignment as value`), więc nie przejdzie po cichu. Ulga w porównaniu z innymi językami.
- **Nieosiągalna gałąź** — `if x > 10 { } else if x > 5 { } else if x > 8 { }`: trzeci warunek nigdy się nie wykona, bo drugi go pochłonie. Kompilator **nic nie powie**. Warto sprowokować.
- **Porównywanie `float64` przez `==`** — z lekcji 2.2: `0.1+0.2 == 0.3` to `false`. W warunkach porównuj z tolerancją: `math.Abs(a-b) < 0.0001`.
- **Zmienna z instrukcji inicjującej nie żyje poza `if`** — to cecha, nie błąd, ale zaskakuje.

## Notatki tutora
- **Instrukcja inicjująca (`if x := ...; ...`) jest ważniejsza, niż się wydaje** — uczeń zobaczy ten zapis w każdym kodzie Go, zwłaszcza z `err`. Warto poświęcić jej minutę więcej.
- Jeśli uczeń pisze głębokie zagnieżdżenia — **nie poprawiaj od razu**. Niech napisze po swojemu, potem zapytaj: "policz, ile poziomów wcięcia ma najgłębsza linia. Da się płycej?"
- Jeśli uczeń zna trójargumentowy `? :` skądinąd i narzeka na jego brak — powiedz, że to celowa decyzja, i pokaż, że `if`/`else` na 4 linie czyta się bez zastanowienia.
- **Nie wprowadzaj `switch`** — to następna lekcja. Jeśli uczeń napisze pięć `else if` pod rząd i zapyta "czy nie da się krócej" — odpowiedz "brawo, właśnie o tym jest 3.2".
